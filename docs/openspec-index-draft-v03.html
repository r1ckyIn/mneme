先回答你"没看懂的问题 3" — proactive-recall 是啥？

用大白话讲：AI 不只是"你问 → 它答"，还要主动浮出相关历史。

举例 — 你打开新 chat 问 COMP3221 这周作业，普通 AI 等你说完才答。但 mneme 的 AI 应该这样开口：

"上周二你卡在 graph shortest-path tutorial 第 3 题，跟这周 BFS 是关联的。先看那道题再做这周可能更顺。"

你没问，它先讲。这就是 KP-07"懂我"的承诺。验收指标：一周样本中，每会话 ≥3 次主动浮出，相关度 ≥90%。

它横跨 3 个 spec 协同：

  • memory-engine — 提供数据（KG 里要有"上周二卡在第 3 题"这条记忆）
  • multi-session — 决定何时触发（新 chat 开场 / 用户说"卡住了" / 拐到新话题）
  • per-course-rules — 决定怎么注入 prompt（COMP3221 的规则说"主动召回历史错误"）
⚠ 待你决定：这个 spec 保持独立横切（v0.2 当前画法），还是合进 memory-engine 里？合进去的话，memory-engine 内部分章节说"触发时机由 multi-session 调用"。不急定，回头再说。

01 claude-subprocess v0.3 加预热约束 v1 Phase 1 执行中 partial

Tauri 2 壳通过 tauri-plugin-shell 启动本机 claude CLI 子进程，stream-json 解析、tool-use roundtrip、subprocess 生命周期。整个项目的命脉。

Phase 1 finding (2026-05-11)：实测发现 app 启动后 claude 子进程不预热 → 用户首条消息冷启动慢（要等 spawn + 模型初始化）。
新增实施约束
app 启动时即 spawn 一个 idle subprocess（不阻塞 UI），处于待命状态；用户首次发送时直接 attach 到已暖好的进程，避免 spawn 延迟。
落地位置：Phase 1 收尾 或 Phase 2 plan 阶段决定（实现细节 — warm pool / default session / pre-spawn 哪个方案待 plan-phase）。
