# Phase 02.1 Plan 02.1-04: W6 GREEN — course-code minimal validator Summary

W6 (dogfood-killer regex `^[A-Z]{4}\d{4}$` that rejected real USYD codes like `COMP3027L` and `BIOL2010S2`) is fixed by replacing both `VALID_COURSE_CODE` (vault_writer.rs) and `VALID_COURSE_RE` (import_controller.rs) with a single shared `vault_writer::validate_course_code` free function — the Wave 0 RED test in `course_code_validation.rs` (4 fns / ~30 cases) flips GREEN, no existing security tests regress, and `SECURITY.md` gains an Audit 2026-05-17 (Phase 02.1) section documenting the T-2-06 mitigation transition.

## What Was Built

### `src-tauri/src/vault_writer.rs` — `pub fn validate_course_code`

- **Removed:** the `VALID_COURSE_CODE: Lazy<Regex>` static at L95-96 + the now-unused `once_cell::sync::Lazy` and `regex::Regex` imports at L41-42.
- **Added:** `pub fn validate_course_code(code: &str) -> Result<(), VaultWriterError>` per CONTEXT D-03 verbatim:
  - trim surrounding whitespace
  - reject empty (after trim)
  - reject > 32 chars (after trim)
  - reject `/`, `\`, `\0` (path separators + null)
  - reject `.` or `..` (parent / self refs)
  - reject all-non-alphanumeric strings
  - accept everything else (alphanumeric / dash / unicode)
- **Swapped:** `create_course` call site at L256 — `if !VALID_COURSE_CODE.is_match(code) { return Err(...) }` → `validate_course_code(code)?;` (4-line block → 1 line).
- **Disposition marker:** `W6 fix` doc-comment header on the new function cites CONTEXT D-03 + UI-REVIEW.md L150 + the existing is_under_source two-arm canonicalize gate as the actual security wall.
- **WR-11 partial fix preserved:** the empty-root / non-absolute-root checks added by 02-15 (lines 246-255) are untouched — verified by `grep -n 'WR-11' src-tauri/src/vault_writer.rs` returning the same 2 hits.

### `src-tauri/src/import_controller.rs` — delegation to shared validator

- **Removed:** the `VALID_COURSE_RE: Lazy<Regex>` static at L163-165 (3 lines of inline-qualified `once_cell::sync::Lazy::new(|| regex::Regex::new(...))`).
- **Changed:** `validate_inputs` body — `if !VALID_COURSE_RE.is_match(c) { return Err(...) }` → `crate::vault_writer::validate_course_code(c).map_err(|e| format!("invalid course code: '{c}' — {e}"))?;`. The IPC return type stays `Result<_, String>` (Tauri boundary requires it); the `map_err` preserves the load-bearing `invalid course code: '...'` prefix so the W5 02.1-05 classifier in `src/lib/import-error.ts` can still extract the raw tail.
- **Disposition marker:** `W6 fix` comment above the changed block cites CONTEXT D-03 and the W5 02.1-05 prefix-preservation contract.

### `src-tauri/tests/course_scaffold.rs` — reject-case update

The old `rejects_invalid_course_code` test asserted `"abc"` (3 lowercase chars) reject — that passed under the regex (case mismatch) but is now legitimately accepted by the minimal validator (3 alphanumeric, no path separator). Replaced with `"../etc"` which rejects under BOTH the old regex AND the new validator. The test still proves `VaultWriterError::InvalidCourseCode(_)` is returned — the only thing that changes is the test data.

### `src-tauri/tests/import_controller_validates_course_category.rs` + inline mirror — reject-case update

Same kind of update: `"not-a-course"` was rejected by the regex (no `[A-Z]{4}\d{4}$` match) but is accepted by the new validator (alphanumeric + hyphen with no path separator). Replaced with `"../etc"`. The integration test in `tests/` and its inline-mirror unit test inside `import_controller.rs::tests::invalid_course_or_category_rejected_before_spawn` were both updated in lockstep.

## Deviations from Plan

### [Rule 1 — Bug pinning regex overdefense] Updated test data in two pre-existing tests

**Found during:** Task 1 verification (`course_scaffold::rejects_invalid_course_code` failed) and Task 2 read-first (`import_controller_validates_course_category` would fail on `"not-a-course"`).

**Issue:** Two pre-existing tests asserted `VaultWriterError::InvalidCourseCode` reject for inputs that the new minimal validator legitimately accepts:

| Test | Old reject input | Why old regex rejected | Why new validator accepts |
|------|------------------|------------------------|---------------------------|
| `course_scaffold::rejects_invalid_course_code` | `"abc"` | 3 lowercase chars, no digits — `^[A-Z]{4}\d{4}$` fails | 3 alphanumeric chars, no path separator → ACCEPT per CONTEXT D-03 |
| `import_controller_validates_course_category::rejects_invalid_course_or_category_before_spawn` + inline mirror | `"not-a-course"` | Hyphen + lowercase — `^[A-Z]{4}\d{4}$` fails | Alphanumeric + hyphen, no path separator → ACCEPT per CONTEXT D-03 |

Both tests were pinning the dogfood-killer overdefense — exactly the wrong-layer regex behavior that CONTEXT D-03 is fixing. Continuing to assert these reject-cases would mean keeping the regex in some form.

**Fix:** Replaced the rejected inputs with `"../etc"` — a real path-poison sentinel that rejects under BOTH the old regex AND the new validator. The assertions themselves (`matches!(err, VaultWriterError::InvalidCourseCode(_))` / `err.contains("invalid course code")`) remain unchanged, proving the validator surface still rejects path-poison while accepting legitimate course codes.

**Files modified:** `src-tauri/tests/course_scaffold.rs`, `src-tauri/tests/import_controller_validates_course_category.rs`, and the inline `tests` module in `src-tauri/src/import_controller.rs` (kept in lockstep with the integration test by the plan's frontmatter).

**Why this is Rule 1 not Rule 4:** This is a test-data update to remove a pinned bug — not an architectural decision. The plan's Task 2 STEP E explicitly anticipated this case ("If a test asserts `BIOL2010S2` should REJECT (false-positive pinning the old buggy behavior), UPDATE that test to assert ACCEPT — note the change in commit message body"). The change is folded into Tasks 1 and 2 commits with full disposition comments inline.
