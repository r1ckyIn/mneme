### D-02 — B3 keychain-friendly `claude_auth_check` (Recommended-accepted)

Replace `Path::new(home).join(".claude").join(".credentials.json").exists()` with a subprocess invocation via `std::process::Command` (the Rust analog of execFile — argv is passed as a separate vec, never shell-interpolated):

```rust
let output = std::process::Command::new("claude")
    .arg("--version")
    .output();
match output {
    Ok(o) if o.status.success() => ClaudeAuthStatus { found: true, version: parse_version(&o.stdout), env_broken: false },
    Ok(_) => ClaudeAuthStatus { found: false, version: None, env_broken: false },
    Err(e) if e.kind() == NotFound => ClaudeAuthStatus { found: false, version: None, env_broken: false },
    Err(_) => ClaudeAuthStatus { found: false, version: None, env_broken: true },
}
```

**Why subprocess (not keychain probe directly)**:
- Single source of truth: if `claude --version` works, the CLI is usable end-to-end (PATH ok + keychain ok + binary ok). Probing keychain only checks one of three.
- Cross-version forward-compat: future Claude Code keychain schema changes don't break our probe.
- Cost: ~100ms one-shot subprocess at onboarding Step 2 — acceptable for a one-time check (no per-import overhead).

**Trade-offs accepted**:
- Onboarding Step 2 spinner shows for 100-300ms instead of instant. Add "Checking…" copy.
- If user has 100s of `claude` binaries in PATH, spawn uses first match — same as ALL Claude Code invocations everywhere.

**Tauri capability gate**: Add `core:command:execute` permission for `claude` binary with regex `^--version$` arg validator. Update `audit-capabilities.sh` whitelist (single arg, no wildcard).

### D-03 — W6 course code validator (Recommended-accepted, user-validated rationale)

**Remove `VALID_COURSE_RE` + `VALID_COURSE_CODE` regex entirely.** Replace with minimal path-safe validator in `vault_writer.rs`:

```rust
pub fn validate_course_code(code: &str) -> Result<(), VaultWriterError> {
    let trimmed = code.trim();
    if trimmed.is_empty() {
        return Err(VaultWriterError::InvalidCourseCode("course code empty".into()));
    }
    if trimmed.len() > 32 {
        return Err(VaultWriterError::InvalidCourseCode(format!("course code too long ({} chars, max 32)", trimmed.len())));
    }
    if trimmed.contains('/') || trimmed.contains('\\') || trimmed.contains('\0') {
        return Err(VaultWriterError::InvalidCourseCode("course code contains path separator or null".into()));
    }
    if trimmed == "." || trimmed == ".." {
        return Err(VaultWriterError::InvalidCourseCode("course code cannot be '.' or '..'".into()));
    }
    if trimmed.chars().all(|c| !c.is_alphanumeric()) {
        return Err(VaultWriterError::InvalidCourseCode("course code needs at least one alphanumeric char".into()));
    }
    Ok(())
}
```

**Both call sites (`vault_writer::create_course` + `import_controller::validate_inputs`) call the same validator.** Tests:
- accepts: `COMP3027`, `COMP3027L`, `BIOL2010S2`, `MATH1062`, `XYZ`, `cs-101` (lowercase + hyphen ok), `日本語1` (unicode alphanumeric ok)
- rejects: `""`, `"   "`, `"../etc"`, `"a/b"`, `"\0nul"`, `"."`, `".."`, `"!!!"` (no alphanumeric), 33-char string

**Defense rationale (user's question answered)**: Path traversal (T-2-01) + symlink (T-2-02) are closed by `vault_writer::is_under_source` two-arm canonicalize — verified by `path_traversal_blocked.rs` + `symlink_canonicalize_blocked.rs` + SECURITY audit (block-on-HIGH gate passed). The regex was overdefense — cost of rejecting `COMP3027L` (real USYD code) > benefit of redundant string-level path-injection wall.

**SECURITY.md update**: Add `## Audit 2026-05-17 (Phase 02.1)` section noting T6 (IPC arg injection) mitigation now via `validate_course_code` minimal-validator + existing `Path::join` semantics (no shell), instead of regex prefilter. Mitigation strength unchanged (still LOW residual).

### D-05 — W2 Onboarding step transition (Recommended-accepted)

Add Svelte `transition:fly` to each Step component's root wrapper:

```svelte
<script>
  import { fly } from 'svelte/transition';
  import { quintOut } from 'svelte/easing';
  import { prefersReducedMotion } from '$lib/motion';   // new helper
</script>

<div transition:fly={{ y: prefersReducedMotion() ? 0 : 8, duration: 220, easing: quintOut, opacity: 0 }}>
  <!-- step content -->
</div>
```

**`prefers-reduced-motion` helper**: new `src/lib/motion.ts` exports `prefersReducedMotion(): boolean` via `window.matchMedia('(prefers-reduced-motion: reduce)').matches`. Falls back to `false` in SSR.

**Why Svelte builtin (not GSAP / animejs)**:
- KP-02 (50% OSS rule) — Svelte transitions are tree-shaken, zero added dep
- KP-09 motion philosophy — subtle is the brand; 220ms ease-out matches Anthropic/Claude family curves per KD-13
