<objective>
Wave 1 GREEN for W5 (WARNING — UX defect surfaced by dogfood #8). UI-REVIEW.md L155-158: `classifyImportError` returns the generic "Something went wrong while importing. Check the console for details, or try again." string when no classifier branch (`dest-clash:` / permission-denied) matches the raw IPC error. During dogfood, the message `invalid course code: "DOGFOOD101"` was hidden behind devtools — the user had to open devtools to understand WHY the import failed. The W5 fix surfaces the raw error tail (last colon segment) as an inline second-line surface so users see e.g.:

`Something went wrong while importing. Check the console for details, or try again. (details: invalid course code: 'DOGFOOD101' — course code rejected)`

The friendly headline stays calm; the technical tail is added in `(details: ...)` form so users have a self-recovery cue without leaving the app.

**Why last colon (not first):** Errors often wrap multiple levels of context. `"io error: vault writer error: validation failed: course code 'DOGFOOD101' rejected"` — the FIRST colon gives the user `"vault writer error: validation failed: course code 'DOGFOOD101' rejected"` which still contains the same wrappers. The LAST colon gives `"course code 'DOGFOOD101' rejected"` — the actual signal. This is the pattern Test 5 in 02.1-01 Task 3 pins.

**Why classifier branches go first:** The structured branches (DEST_CLASH_MESSAGE / DUPLICATE_PERMISSION_DENIED_MESSAGE) are user-friendly canned copy that does not benefit from raw enrichment — those errors are by-design routed to specific advice ("rename your file" / "delete the old file first"). The fallback enrichment runs ONLY when no classifier matched, i.e. the catch-all "unknown error shape" path.

**Why TDD:** The transformation is parameterized over raw error strings with deterministic accept/reject cases. Wave 0 02.1-01 Task 3 landed 5 cases in `tests/import-error-fallback.test.ts`; this plan adds the production logic that turns Tests 1 + 5 GREEN (Tests 2 / 3 / 4 already pass on first run).

The TDD framing is justified by the Wave 0 RED-test contract — we already wrote the tests, this plan writes the code that satisfies them. No separate RED commit needed in this plan (Wave 0 owns RED).

```ts
// NEW pure helper:
export function extractRawTail(raw: unknown): string {
    const text = errorToString(raw);  // existing internal helper
    if (!text) return "";
    const lastColon = text.lastIndexOf(":");
    if (lastColon === -1) return "";          // no colon → no tail
    const tail = text.slice(lastColon + 1).trim();
    return tail;
}

// classifyImportError CHANGES the fallback branch:
export function classifyImportError(raw: unknown): string {
    if (isDestClashShape(raw)) return DEST_CLASH_MESSAGE;
    if (isPermissionDeniedShape(raw)) return DUPLICATE_PERMISSION_DENIED_MESSAGE;
    // W5 fix — fallback enrichment:
    const tail = extractRawTail(raw);
    if (tail.length === 0) return GENERIC_IMPORT_ERROR_MESSAGE;
    return `${GENERIC_IMPORT_ERROR_MESSAGE} (details: ${tail})`;
}
```
