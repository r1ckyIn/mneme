## Decisions

### Wrapper-span (Option A) over component-prop for drag-region exclusions
Wrap `<ImportStatusPill />` in `<span class="no-drag-wrap" data-tauri-drag-region="false">` with `display: contents` CSS instead of adding a `dragRegion?: "false" | undefined` prop to the pill component. **Rationale:** Parallel-wave plans must be file-disjoint. Wrapper-span gives the same DOM effect without forcing a prop API change on a shared component. `display: contents` keeps the wrapper layout-invisible.
**Source:** 02.1-12-SUMMARY.md "Decisions Made" (W8 titlebar drag fix)

### Field-by-field MERGE (not REPLACE) for `onMount` + persisted state
After `load_onboarding_state` resolves, MERGE each field individually into the live `$state` object instead of reassigning the whole binding. Per-field merge rules: `vault_path = live || loaded` (non-empty live wins), `courses_added = live.length > 0 ? live : loaded`, `completed_at = loaded ?? live` (monotonic flip wins), `current_step = initialStep` (URL truth).

**Rationale:** WR-007 fix — the original `onboardingState = { ...loadedState, current_step: initialStep }` REPLACE clobbered any user mutation (e.g. Step 3 `setVaultPath`) that happened DURING the load IPC await. Per-field merge preserves in-flight user intent.
**Source:** 02.1-REVIEW-FIX.md iter 2 + 02.1-12-SUMMARY.md verification

### macOS BSD `mktemp` does not expand X's in the middle of a suffix pattern
`mktemp /tmp/gsd-pr-body.XXXXXX.md` created a LITERAL file `gsd-pr-body.XXXXXX.md` (X's not expanded). BSD `mktemp` only expands X's that appear as the LAST chars of the template before the optional suffix. Fix: use `mktemp -t pattern` or accept the literal path (since it's unique enough for single use).

**Context:** When using `mktemp` in cross-platform scripts, the suffix-after-X pattern is non-portable. GNU coreutils handles it; macOS BSD doesn't. Workaround: put X's at the absolute end or invoke `gmktemp` if `brew install coreutils`.
**Source:** Session bash output during ship-workflow PR body generation

### Cherry-picking 95 commits cascades to all-conflict when one early commit deletes 137 files
Initial PR-branch strategy attempted to cherry-pick 95 code-touching commits from 187 local commits. The first commit (`e1564d2 docs(state): record phase 2 context session`) deleted 137 `.planning/phases/00-*` / `01-*` / `01.1-*` / `01.2-*` files (Phase 02 entry cleanup). ### Bridge stderr JSON envelope makes failure modes greppable
`gsd-dev-screenshot.mjs` exits non-zero with structured stderr JSON (`{"error":"mneme window not frontmost (start cargo tauri dev first)"}`) when the dev server is down. The GSD SDK `verify.*` handlers parse this envelope and propagate to verify-work. Without the JSON envelope, fallback decisions (skip auto-screenshot vs abort) would have to grep human-readable error text.

**Context:** Pattern for any CLI bridge in a multi-process verification pipeline: emit `{"error":"<message>","hint":"<recovery>"}` on stderr + non-zero exit. Consumers parse JSON; humans read the same string. Saves a custom error-class hierarchy.
**Source:** 02.1-UAT.md `auto_verified` block + `scripts/gsd-dev-*.mjs` headers

### gsd-validate-commit hook can't parse heredoc commit messages — use multiple `-m` flags
`git commit -m "$(cat <<EOF...EOF)"` is parsed by the hook as `subject = $(cat`, triggering CONVENTIONAL_COMMITS_VIOLATION. Multi-`-m` flag form (`-m subject -m body-para-1 -m body-para-2`) works cleanly. (This is in the user's memory layer already, surfaced again in Phase 02.1 commits.)

**Context:** When orchestrators / agents need rich multi-paragraph commit messages, prefer multiple `-m` flags over heredoc — it survives the hook's regex AND preserves paragraph structure in `git log --pretty=full`.
**Source:** `feedback_gsd_validate_commit_heredoc` memory entry + 02.1 commit history pattern

### `vi.mock` factory hoisting requires `vi.hoisted()` for captured variables
Mock factory `vi.mock("@tauri-apps/api/core", () => ({ invoke: invokeMock }))` failed because `invokeMock` was declared at top-level scope but `vi.mock` is hoisted ABOVE imports — `invokeMock` is undefined at factory-eval time. Fix: declare captured variables inside `vi.hoisted(() => ({...}))` block so they hoist with the mock.

**Context:** Vitest mock factories cannot reference any non-hoisted top-level variable. Either move the variable into `vi.hoisted()` OR construct the mock without external captures.
**Source:** `tests/import-dialog-auto-close.test.ts` G-01 test development

## Patterns

### Code-review `--fix --auto` iteration loop (3 cycle convergence)
Run `/gsd-code-review N --fix --auto`. Iter 1 applies fixes. Iter 2 re-reviews + catches any regressions induced by iter 1. Iter 3 (if needed) cleans up. Auto-exits when re-review reports `status: clean`.

**When to use:** Any fix wave that touches state-machine / async-load / race-window logic. Don't bother with `--auto` for pure visual or token-discipline fixes (those are idempotent w.r.t. each other).
**Source:** 02.1-REVIEW.iter2.md → iter3.md convergence

---

### Nyquist gap-fill audit retroactively pins fix-layer behavior
After `--fix --auto` lands, run `/gsd-validate-phase N`. Audit produces a gap table: for each fix commit, is there a regression test? Spawn `gsd-nyquist-auditor` agent to write the missing tests (NOT modify impl). Phase 02.1 added 4 gap-fill tests (`tests/onboarding-step6-double-click.test.ts`, `src-tauri/tests/atomic_write_extensionless.rs`, `src-tauri/tests/cancel_all_nonblocking.rs`, `tests/import-dialog-auto-close.test.ts`).

**When to use:** After ANY code-review fix loop closes. Gap-fill tests are cheap (1-3 tests per finding) and prevent the exact same bug from re-emerging in the next code-review cycle.
**Source:** 02.1-VALIDATION.md + 4 gap-fill test commits

### Squash + filter PR branch (when local history has rich .planning/ noise)
Solo-dev pattern: local main accumulates 187 atomic commits (fix + docs + planning churn). For PR: create `phase-N-pr` branch from `origin/main`, `git diff origin/main..main -- ':!.planning/phases' ':!.planning/seeds' ':!.planning/threads' ... > patch`, `git apply --index patch`, commit as 1 squash commit with comprehensive body listing every delivered piece. Push + open PR. Local main stays diverged from origin/main forever (by design).

**When to use:** Any solo-dev workflow where commits-on-main is the norm AND reviewers want clean PR diffs. Cherry-pick falls apart when local history has large-delete commits (see Lesson #5).
**Source:** Session execution of `/gsd-pr-branch main` → squash strategy after cherry-pick failed

Need to change behavior of a component owned by a PARALLEL Wave plan? Wrap it: `<span class="no-drag-wrap" data-tauri-drag-region="false"><InnerComponent /></span>`. Use `display: contents` to keep wrapper layout-invisible.

**When to use:** Tauri drag-region carve-outs, accessibility role overrides, data-attribute injection — anywhere parent-context needs to alter child behavior without touching the child file. Parallel-wave plans become file-disjoint by construction.

### Comment-stripped source view for regex pin tests
```ts
function codeOnly(source: string): string {
  return source
    .replace(/\/\*[\s\S]*?\*\//g, "")
    .replace(/\/\/[^\n]*/g, "")
    .replace(/<!--[\s\S]*?-->/g, "");
}
```
Use the stripped view when asserting "the pre-fix shape no longer appears in the source". Comments quoting historical bugs (for explanation) won't false-positive the not-match assertion.

**When to use:** Any regression test that pins absence of a code pattern. Always strip comments first; otherwise an explanatory block that quotes the pre-fix shape verbatim breaks the test.
**Source:** `tests/onboarding-resume.test.ts` WR-007 source pins + `tests/import-dialog-auto-close.test.ts` G-01 source pins

### Bridge stderr JSON envelope for multi-process verification pipelines
CLI bridge scripts (`scripts/gsd-dev-*.mjs`) exit non-zero with structured stderr JSON: `{"error":"<msg>","hint":"<recovery>"}`. SDK consumers parse JSON; human callers see the same string. No custom error-class hierarchy needed.

**When to use:** Any CLI bridge feeding into a multi-step verification pipeline (verify-work, ship preflight, CI gates). Standard for any new bridge script.
**Source:** `scripts/gsd-dev-*.mjs` header comments + D-BR-02 contract

### macOS unsigned dev-build mneme appears as a "process" but NOT as an AppleScript "application"
