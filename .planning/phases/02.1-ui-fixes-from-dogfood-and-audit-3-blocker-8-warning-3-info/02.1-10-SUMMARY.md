## Decisions Made

1. **Honor plan-spec richer CSS rule, NOT bare-bones Step 5 duplication.** Step 5 / Step 2 / Step 6 ghost-link rules are 9-LOC each (background/border/color/font/text-decoration/cursor/padding + 1 :hover). The plan-spec requested a richer 35-LOC rule with margin-top, padding-pair, border-radius, transition, `:focus-visible` orange-ring, and `:disabled` opacity treatment. Honored the plan-spec because it captures the Phase 2 unified focus-ring contract (W3 + W4 are both Wave 2, both establish the `:focus-visible` standard for onboarding ghost surfaces). This new rule is the Phase 2 reference; legacy bare-bones rules in Step 5 / 2 / 6 are now technical debt for a future single-file refactor.

2. **Do NOT lift to `src/lib/styles/links.css` in this plan.** The lift would touch 4 Svelte components (Step 5, Step 2, Step 6, Step 3) + a new shared CSS file. That would (a) break Wave 2 file-disjointness (Plan 10 currently owns ONE file: Step3VaultPicker), (b) require visual regression checking on the 3 Step components that currently work, and (c) exceed the scope-boundary defined in `<deviation_rules>`. Captured as a backlog refactor candidate in the file header comment + this SUMMARY's `affects:` frontmatter.

3. **`disabled={saving}` mirrors primary Browse button at L143-144.** Without this guard, the user could trigger a new file picker while `vault_create_scaffold` is in flight, racing the picker dialog against the IPC response. Already encoded for the primary Browse; the secondary ghost-link must match.
