# Phase 02.1 Plan 02.1-12: W8 GREEN — TitlebarMeta enables window drag from right half

**Removes the blanket `-webkit-app-region: no-drag` CSS from `.titlebar-meta` (a Tauri 1 / Electron carry-over that overrode the Tauri 2 HTML attribute on WKWebView), and wraps the ImportStatusPill in a `display: contents` span carrying `data-tauri-drag-region="false"` so clicks on the pill still fire `mneme:open-history` rather than starting a window-move.**

## Accomplishments

- Window can now be dragged from the right half of the 36px titlebar (dot, dot-sep, meta-text spans) — drag was previously broken because `.titlebar-meta` had a blanket Tauri 1 / Electron-era `-webkit-app-region: no-drag` declaration that overrode the parent `.titlebar`'s `data-tauri-drag-region` attribute on WKWebView.

Achieved via an EXTERNAL wrapper `<span class="no-drag-wrap" data-tauri-drag-region="false">` with `display: contents` CSS — wraps the pill without touching `ImportStatusPill.svelte` source (file ownership preserved for parallel Wave 2 plans 02.1-07 / 02.1-13).

## Live Drag-Test Outcome (reasoning-based per `<parallel_execution>` directive)

Per the `<parallel_execution>` directive in the spawn prompt ("Test by verifying the empty space between text and cog still drags the window (live dogfood after merge). ... verified by reasoning — actual dogfood deferred"), the `checkpoint:human-verify` Task 2 is satisfied by source-level reasoning rather than a live `npm run tauri dev` session in this worktree. Reasoning trace:

1. **Right-half drag works** — `.titlebar-meta` CSS no longer contains any `-webkit-app-region` declaration (grep = 0). The parent `.titlebar` retains `data-tauri-drag-region` at `+page.svelte` L165. On WKWebView, Tauri 2's drag detection walks up the DOM tree from the click target until it finds the nearest ancestor with `data-tauri-drag-region` set (and no closer ancestor with `data-tauri-drag-region="false"`). The neutral children of `.titlebar-meta` — `.dot`, `.dot-sep`, the two `.meta-text` spans — have no carve-out attribute, no click handler, and no app-region CSS, so click events on them resolve to the parent `.titlebar`'s drag affordance. Drag-from-right-half works.

2. **Settings cog click works** — L101 retains `data-tauri-drag-region="false"` (verified in source). When Tauri 2's drag detection walks up from the cog button, the FIRST attribute it hits is the cog's own `"false"` carve-out, short-circuiting before reaching the parent's drag affordance. The cog's `onclick={openSettings}` handler fires normally and dispatches `mneme:open-settings` — which `+page.svelte`'s `onOpenSettingsEvent` handler at L123-125 catches and sets `settingsOpen = true`.

3. **ImportStatusPill click works** — The pill is now wrapped in `<span class="no-drag-wrap" data-tauri-drag-region="false">` (L91). Tauri 2's drag detection walks up from a click on the pill button, hits the wrapping span's `"false"` attribute, short-circuits. The pill's `onClick` prop (wired to `openHistory` in TitlebarMeta) dispatches `mneme:open-history` — which `+page.svelte`'s `onOpenHistoryEvent` handler at L127-129 catches and sets `historyOpen = true`. The pill's button receives the click as normal.

4. **Layout integrity** — `display: contents` removes the wrapper's own box from the layout tree. The pill becomes a direct flex item of `.titlebar-meta`'s `display: flex` row, exactly as it was before the wrapper was added. The `gap: var(--space-3)` between flex items is unchanged. The pill's position between the connection-status text and the dot-sep is identical to the pre-fix layout.

5. **Left-half drag still works (no regression)** — The blank left half of the titlebar is owned by `<div class="titlebar-spacer">` at `+page.svelte` L166. This element has no app-region CSS and inherits drag from its parent `.titlebar`'s `data-tauri-drag-region` attribute. This plan made zero changes to `+page.svelte` or the spacer, so left-half drag behavior is preserved by construction.

The live `npm run tauri dev` dogfood is queued for the orchestrator's post-Wave-2 visual review — it will verify items 1-5 by observation rather than reasoning, and any deviation from the predicted behavior will be filed as a Rule 1 bug against this plan with the worktree branch still available for amendment.

## Forward Reference / Backlog Seed

**If a future plan adds another interactive child to TitlebarMeta** (e.g. a notification bell, sync-status icon, network-quality indicator, multi-vault switcher dropdown), it MUST carve out via:

- **Per-button**: add `data-tauri-drag-region="false"` directly on the `<button>` / `<a>` / interactive element (e.g. the existing settings cog at L101 of this file).

Without one of these carve-outs, clicks on the new interactive child will be swallowed by the OS drag affordance and the child's `onclick` handler will never fire.

This is documented in the file header comment (L43-52) and the `.no-drag-wrap` CSS rule comment (L145-151).
