### CR-001: W6 course-code relaxation is Rust-only — both frontend validators still reject real USYD codes

**Files modified:**
- `src/lib/onboarding-validation.ts`
- `src/lib/components/settings/VaultCategory.svelte`
- `tests/course-code-regex.test.ts`

**Commit:** `0905ce4`

**Applied fix:** Replaced the strict `^[A-Z]{4}\d{4}$` regex in `onboarding-validation.ts` with the same minimal path-safe contract the Rust side adopted in W6 — trim, length 1..=32, reject `/`, `\`, `\0`, `.`, `..`, and require at least one Unicode alphanumeric character. The `VaultCategory.svelte` inline duplicate validator was deleted; it now imports the shared `validateCourseCode` from `$lib/onboarding-validation`. Updated `tests/course-code-regex.test.ts` to mirror the Rust integration test (`src-tauri/tests/course_code_validation.rs`) — `BIOL2010S2`, `COMP3027L`, `cs-101`, `日本語1`, `MATH1062` all now pass; `../etc`, `a/b`, `\0nul`, `.`, `..`, 33-char overlength all reject. 30 tests pass; `svelte-check` reports 0 errors / 0 warnings.

### WR-001: Step 6 demo import has no double-click guard

**Files modified:** `src/lib/components/onboarding/Step6DemoImport.svelte`

**Commit:** `043806d` (combined with WR-005 — same call site)

**Applied fix:** Added local `let importing = $state(false)` flag. `browseFile()` now bails early if `importing || saving`, flips the flag for the duration of the `open() + invoke()` round-trip, and resets in `finally`. Threaded `disabled={saving || importing}` onto the dropzone `<button>`, mirroring the discipline parent's `next()`/`finish()` use with `saving`. Double-click on the dropzone now opens at most one OS picker and fires at most one `start_import` IPC per round-trip.

### WR-002: `atomic_write` produces `foo..tmp` for extensionless files

**Files modified:** `src-tauri/src/vault_writer.rs`

**Commit:** `55805ad`

**Applied fix:** Replaced `path.with_extension(format!("{}.tmp", ...))` with `path.set_file_name(format!("{name}.tmp"))`. The previous formulation treated `.tmp` as a literal extension, producing `Makefile..tmp` for extensionless inputs. New behavior is single-dot for every input shape (`foo.pdf` → `foo.pdf.tmp`, `INDEX.md` → `INDEX.md.tmp`, `Makefile` → `Makefile.tmp`). Inputs with no file name (e.g. `/`) now error with `InvalidInput` instead of silently writing to the parent. Pinned by a new `vault_writer::tests::atomic_write_handles_extensionless_input_without_double_dot` unit test that walks the tempdir post-write and asserts no `..` artifact survives.

### WR-003: `cancel_all()` blocks the Tauri event loop via `tauri::async_runtime::block_on`

**Files modified:** `src-tauri/src/lib.rs`

**Commit:** `c138e94`

**Applied fix:** Both `WindowEvent::CloseRequested` and `RunEvent::ExitRequested` handlers now use `tauri::async_runtime::spawn` instead of `block_on`. Mirrors the BL-01 "caller returns immediately" discipline established in `kill_pgid` (lines 80-94). Token flips inside `cancel_all` are themselves race-free; spawned import tasks observe them on next yield. Future maintainers reading the BL-01 comment will no longer find a contradicting `block_on` two functions later. If `cancel_all` ever grows a slow await (flushing import progress to disk on shutdown), this detach is what keeps Cmd+Q from showing a spinning beach ball. `cargo check --all-targets` clean.

### WR-004: `Onboarding.next()` silent no-op when `!loaded` swallows fast Step 3 clicks

**Files modified:**
- `src/lib/components/onboarding/Onboarding.svelte`
- `tests/onboarding-resume.test.ts`

**Commit:** `deb587e`

**Applied fix:** Adopted option (b) from the review — queue the request when `!loaded` and replay it once load resolves. Split the previous one-line gate `if (saving || !loaded) return;` into two gates: `saving` returns silently (a save is already in flight); `!loaded` sets `pendingNext = true` and returns. `onMount` checks `pendingNext` after flipping `loaded = true` and replays via `void next()`. Closes the silent no-op path where a fast Step 3 "Use this path" click before the initial `load_onboarding_state` IPC resolved would mutate `vault_path` and then drop the navigation request. The existing source-file regex pin in `tests/onboarding-resume.test.ts` was broadened to assert both `saving` and `!loaded` are present as separate early-exit gates AND that `pendingNext` is referenced.

**Note:** This fix introduces new state-management logic. Tier 1 (re-read) + Tier 2 (`svelte-check` 0 errors) + existing source-regex pin all pass, but the queue-and-replay behavior under user-perceived timing is best confirmed by `/gsd-verify-work` dogfood — flag for human verification of the fast-click scenario in the verifier phase.

### WR-005: `Step6DemoImport.imported` swallows multi-file selection

**Files modified:** `src/lib/components/onboarding/Step6DemoImport.svelte`

**Commit:** `043806d` (combined with WR-001 — same call site)

**Applied fix:** When the user picks multiple files (the picker is `multiple: true`), the success line now reads `${paths.length} files (${firstBasename}, …)` instead of just the first basename. Single-file imports retain the same one-name string. The `getImportState().pill_state` subscription approach the review mentioned is deferred — the inline summary closes the user-perceived data loss without adding new state subscriptions in a step that's about to be replaced by the post-onboarding pill.

### WR-006: `compute_dest` falls back to `_inbox/invalid-source-basename` for empty/`.`/`..`

**Files modified:** `src-tauri/src/import_controller.rs`

**Commit:** `2db05a5`

**Applied fix:** Changed `compute_dest`'s return type from `PathBuf` to `Result<PathBuf, &'static str>`. Unusable basenames (`""`, `"."`, `".."`) now `Err("invalid source basename")` instead of silently routing to a fixed sentinel path. The single caller (`start_import_inner`) handles the `Err` by recording a per-file failure with the `invalid-name:` prefix, emitting an `error` status `import:progress` event, incrementing `failed`, and `continue`-ing the batch. `import-error.ts`'s W5 fallback (`extractRawTail`) handles the new prefix automatically — no new classifier branch needed. Pinned by two new module tests: `compute_dest_rejects_unusable_basenames` (parameterized over the 3 unusable basenames) and `compute_dest_happy_path_returns_expected_paths` (covers both course + non-_inbox and `None` + `_inbox` arms).
