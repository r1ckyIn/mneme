## I2 Disposition — ImportHistoryModal header hardcode

**Root cause:** `src/lib/components/ImportHistoryModal.svelte:118` declared `grid-template-rows: 56px 1fr` — the 56px header height (UI-SPEC §8.6) was duplicated as a naked number in the grid track sizing, bypassing the token system. Any future header-height shift would require coordinated edits in (potentially) multiple sites; over time this is exactly how visual contracts drift.

**Fix shape:** Declare a local CSS custom property `--history-header-h: 56px` at `.modal` scope. The grid-template-rows now references `var(--history-header-h)`. The header CSS rule (`.header`) does not currently set an explicit height — grid sizing handles it — so no further change was needed there; the custom property is a one-place single-source for any future header-height tweak.

**Why local custom property (not global `--row-height-md` token):**
- Preflight grep confirmed `tokens.css` defines no `--row-height-*` family.
- UI-SPEC §8.6 specifies the 56px header height ONLY for this modal. Adding a global token for a one-site contract would leak an abstraction without a second consumer to justify it (YAGNI).
- The local-custom-property pattern keeps the contract grep-able (`grep '--history-header-h'` finds both declaration + consumer) without polluting the global token namespace.

**Inline disposition comment** (CSS-block form above the `.modal` rule) cites UI-SPEC §8.6 and explains the local-not-global decision so future readers do not relitigate.

## I3 Disposition — Step1Welcome spacing fragility

**Root cause:** `src/lib/components/onboarding/Step1Welcome.svelte:53-87` used `.step1 { gap: var(--space-5) }` (uniform 20px between children) plus per-child correction margins (`.wordmark { margin-bottom: var(--space-1) }` = +4px = effective wordmark→headline 24px = `--space-6`; `.cta { margin-top: var(--space-5) }` = +20px = effective body→CTA 40px = `--space-10`). Mathematically the rhythm was spec-correct, but the stack was fragile — removing any single piece silently shifts the rhythm because none of the corrections name what they are correcting for.

**Fix shape:** Removed the uniform `gap: var(--space-5)` from `.step1`. Replaced with explicit per-element margins on each component:
- `.wordmark { margin-bottom: var(--space-6) }` — wordmark → headline (24px)
- `.headline { margin: 0 0 var(--space-5) 0 }` — headline → body (20px)
- `.body { margin: 0 }` — no margin-bottom (`.cta` owns the gap-to-next)
- `.cta { margin-top: var(--space-10) }` — body → CTA (40px)

Same visual rhythm. Less fragile. Each gap names itself and its intent via inline comment citing UI-SPEC §8.1.1.

**Why explicit margins over flex gap:** When the spec lists THREE distinct intervals between FOUR elements, a single parent `gap` cannot honestly encode all three — only mathematically reach them via per-child compensations. The component header comment already enumerates the three gaps as canonical hierarchy (line 5-12) — the CSS should reflect that enumeration directly.

**Inline disposition markers** (4 occurrences of `I3 fix` — 1 in `.step1` block-comment + 1 each on `.wordmark` / `.headline` / `.cta`) give grep coverage for future audits.
