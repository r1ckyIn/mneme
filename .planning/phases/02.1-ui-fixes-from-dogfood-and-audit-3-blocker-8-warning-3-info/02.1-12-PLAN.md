<objective>
Wave 2 polish — W8 (WARNING): the app window currently cannot be dragged from the right half of the 36px titlebar because TitlebarMeta.svelte:118 applies `-webkit-app-region: no-drag` to the entire `.titlebar-meta` container. The parent `+page.svelte:165` correctly sets `<div class="titlebar" data-tauri-drag-region>` (Tauri 2 idiom), but the child container's CSS overrides it — net effect, only the blank left half of the titlebar is draggable; the user can't grab the right half (which is most of the chrome).

**Why is `-webkit-app-region: no-drag` a problem?**
- Tauri 2 uses `data-tauri-drag-region` HTML attribute (NOT `-webkit-app-region` CSS) per official docs + existing usage at page.svelte L154/L165. The `-webkit-app-region: no-drag` CSS is a Tauri 1 / Electron legacy idiom; in Tauri 2's WKWebView setup, the attribute is authoritative.
- BUT: the legacy CSS still has effect on WKWebView — it blocks the inherited drag from the parent attribute. So the BLANKET no-drag CSS on .titlebar-meta is what's killing drag on the right half.

**Fix per UI-REVIEW.md L45 + CONTEXT W8:**
1. REMOVE `-webkit-app-region: no-drag` from `.titlebar-meta` CSS.
2. ADD `data-tauri-drag-region="false"` to the 2 interactive children: the settings cog `<button class="icon-btn">` (already has it at L84, KEEP) and the ImportStatusPill component's root button (needs to be added — currently has no opt-out).
3. The dot, dot-sep, meta-text spans are neutral — they should inherit drag from the parent (clicking-and-dragging on them initiates window-move per OS).
4. The vault-label span (`<span class="meta-text" title="...">vault: {displayPath}</span>`) has a title attribute hover — drag should still work because span elements don't block the OS drag-initiation by default.

**Why execute (not TDD):** Pure CSS removal + 1-2 attribute additions; no behavior logic. Verification is grep + live drag-test (human-verify required because the OS-drag behavior is the contract surface and can't be unit-tested in jsdom).

**Risk to mitigate (per CONTEXT W8 Risk Register row 5):** W8 drag-region change may break click-through on titlebar interactive children. Carve out `data-tauri-drag-region="false"` on the 2 buttons (cog + pill); dev-loop verify after wire. The human-verify checkpoint covers this — if pill click stops working, REVERT and add the attribute on a deeper child if needed.

**Out of scope:**
- Top-LEFT traffic light area (macOS native chrome — handled by `titleBarStyle: "Overlay"` per tauri.conf.json L9-11; NOT touchable from CSS).
- Drag from outside the 36px titlebar region (intentional — only the titlebar is draggable per macOS UX convention).
- Renaming `data-tauri-drag-region` to anything else — Tauri-internal attribute; locked.

**Parallel-safety (Wave 2):** Touches ONE file (`TitlebarMeta.svelte`). No overlap with other Wave 2 plans.
