## B2 Disposition

**Root cause:** UI-SPEC §4 lines 148-153 reserve `--color-success` (the green `#4ea36b` token) for the 3 onboarding validation sites only: Step 2 Claude CLI auth `found` dot, Step 3 vault path picker valid checkmark, Step 5 add-course `typing-valid` / `added` state. The reserved-for list is explicitly exhaustive ("no other surface in Phase 2 uses `#4ea36b`"). `VaultCategory.svelte:371` applied `--color-success` to the "Move vault complete" status message in the Settings panel — a vault move in Settings is not an onboarding validation state.

**Fix:** Single-line token swap to `var(--color-warm-dark-soft)` — the soft warm-tone success color that `ImportStatusPill.svelte:84` already uses for the imported-state pill (called out by UI-SPEC §4 line 153 as the canonical non-onboarding success accent: "The status pill's `imported` state uses `--color-warm-dark-soft`, not green.").

**Disposition comment** (single-line `/* ... */` form to keep grep simple) inserted directly above the changed rule cites UI-SPEC §4 + names the analog so future readers recover the contract without spelunking.
