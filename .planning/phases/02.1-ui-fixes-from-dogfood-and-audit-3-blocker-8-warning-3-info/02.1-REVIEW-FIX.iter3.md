## Iteration 2 (2026-05-18)

### WR-007: WR-004 `pendingNext` replay races with `onMount`'s full-state REPLACE — user mutations on Step 3 can be silently overwritten

**Files modified:**
- `src/lib/components/onboarding/Onboarding.svelte`
- `tests/onboarding-resume.test.ts`

**Commit:** `ca8dfbf`

**Applied fix:** Adopted the reviewer's Option A — replaced the full-state REPLACE at the resolved-load site with a field-by-field MERGE into the live `$state` object. Concretely, `onMount` no longer reassigns `onboardingState = { ...loadedState, current_step: initialStep }`; it now mutates `onboardingState.current_step`, `onboardingState.vault_path`, `onboardingState.courses_added`, and `onboardingState.completed_at` individually with a merge rule that prefers the in-place user mutation when present:

- `vault_path`: `live || loaded` — non-empty live wins (covers the WR-007 race: Step 3 `setVaultPath` wrote `"/Users/qy/StudyVault"` before load resolved).
- `courses_added`: `live.length > 0 ? live : loaded` — same logic for the Step 5 chip click race.
- `completed_at`: `loaded ?? live` — a persisted completion timestamp always wins over a null live (monotonic flip).
- `current_step`: always `initialStep` (URL truth, forward-only wizard — unchanged contract).

This closes the silent-data-loss path documented in REVIEW.md WR-007 where a fast Step 3 "Use this path" click landed before the load IPC resolved, then `pendingNext` replayed `next()` with a vault_path that the REPLACE had clobbered to `""`, persisting a corrupted `~/.mneme/onboarding.json`.

**Test coverage added:** 6 new tests in `tests/onboarding-resume.test.ts`:

- 4 runtime tests in a new `describe("WR-007 fix — onMount merges loaded state into live onboardingState (no REPLACE)")` block. The race is exercised deterministically without a Svelte component mount: the `onMount` merge formula is reproduced in plain TS as an `applyMerge` helper, then a deferred promise simulates the load window with the user's vault_path mutation happening during the await. The expected post-merge invariants are pinned (live vault_path survives; cold-start resume from disk works; Step 5 chip mutation survives; completion timestamp wins via `??`).
- 2 source-regex pin tests in a new `describe("WR-007 fix — Onboarding.svelte source-file invariants")` block. These read the source via `node:fs/promises readFile` and grep for (a) the absence of the pre-fix REPLACE shape `onboardingState = { ...loadedState, current_step: initialStep }`, and (b) the presence of the new field-by-field merge formulas. The not-match pin uses a comment-stripped view of the source so the WR-007 explanatory block (which legitimately quotes the pre-fix shape verbatim) cannot trigger a false negative.

The new tests sit alongside the existing 3 IPC-contract tests + 3 WR-03 source pins, bringing the file to 12 tests (12/12 passing).

**Verification:**
- Tier 1 (re-read): merge formulas confirmed correct; comments accurately describe each case.
- Tier 2 (`npm run check`): `svelte-check` reports 401 files, 0 errors, 0 warnings.
- Targeted vitest: `tests/onboarding-resume.test.ts` — 12/12 pass.
- Full vitest: 305/307 pass (1 skipped, 1 pre-existing env-dependent failure in `scripts/__tests__/visual-review-template.test.mjs` carried over from iter 1 — unrelated to this fix).

**Note:** Logic-fix flagged for `/gsd-verify-work` dogfood. The race is hard to reproduce manually on a fast SSD (sub-50ms window), but the new runtime tests give CI a deterministic guard against re-introducing the REPLACE pattern.

### WR-001: Step 6 demo import has no double-click guard

**Files modified:** `src/lib/components/onboarding/Step6DemoImport.svelte`

**Commit:** `043806d` (combined with WR-005 — same call site)

**Applied fix:** Added local `let importing = $state(false)` flag. `browseFile()` now bails early if `importing || saving`, flips the flag for the duration of the `open() + invoke()` round-trip, and resets in `finally`. ### WR-002: `atomic_write` produces `foo..tmp` for extensionless files

**Files modified:** `src-tauri/src/vault_writer.rs`

**Commit:** `55805ad`

**Applied fix:** Replaced `path.with_extension(format!("{}.tmp", ...))` with `path.set_file_name(format!("{name}.tmp"))`. The previous formulation treated `.tmp` as a literal extension, producing `Makefile..tmp` for extensionless inputs. New behavior is single-dot for every input shape (`foo.pdf` → `foo.pdf.tmp`, `INDEX.md` → `INDEX.md.tmp`, `Makefile` → `Makefile.tmp`). Inputs with no file name (e.g. `/`) now error with `InvalidInput` instead of silently writing to the parent. Pinned by a new `vault_writer::tests::atomic_write_handles_extensionless_input_without_double_dot` unit test that walks the tempdir post-write and asserts no `..` artifact survives.

### WR-003: `cancel_all()` blocks the Tauri event loop via `tauri::async_runtime::block_on`

**Files modified:** `src-tauri/src/lib.rs`

**Commit:** `c138e94`

**Applied fix:** Both `WindowEvent::CloseRequested` and `RunEvent::ExitRequested` handlers now use `tauri::async_runtime::spawn` instead of `block_on`. Mirrors the BL-01 "caller returns immediately" discipline established in `kill_pgid` (lines 80-94). Token flips inside `cancel_all` are themselves race-free; spawned import tasks observe them on next yield. Future maintainers reading the BL-01 comment will no longer find a contradicting `block_on` two functions later. If `cancel_all` ever grows a slow await (flushing import progress to disk on shutdown), this detach is what keeps Cmd+Q from showing a spinning beach ball. `cargo check --all-targets` clean.

### WR-004: `Onboarding.next()` silent no-op when `!loaded` swallows fast Step 3 clicks

**Files modified:**
- `src/lib/components/onboarding/Onboarding.svelte`
- `tests/onboarding-resume.test.ts`

**Commit:** `deb587e`

**Applied fix:** Adopted option (b) from the review — queue the request when `!loaded` and replay it once load resolves. Split the previous one-line gate `if (saving || !loaded) return;` into two gates: `saving` returns silently (a save is already in flight); `!loaded` sets `pendingNext = true` and returns. `onMount` checks `pendingNext` after flipping `loaded = true` and replays via `void next()`. Closes the silent no-op path where a fast Step 3 "Use this path" click before the initial `load_onboarding_state` IPC resolved would mutate `vault_path` and then drop the navigation request. The existing source-file regex pin in `tests/onboarding-resume.test.ts` was broadened to assert both `saving` and `!loaded` are present as separate early-exit gates AND that `pendingNext` is referenced.

**Note:** This fix introduces new state-management logic. Tier 1 (re-read) + Tier 2 (`svelte-check` 0 errors) + existing source-regex pin all pass, but the queue-and-replay behavior under user-perceived timing is best confirmed by `/gsd-verify-work` dogfood — flag for human verification of the fast-click scenario in the verifier phase.

**Iter-2 follow-up:** Iter 2 re-review found this fix introduced WR-007 — the queue replay races with onMount's full-state REPLACE and clobbers user mutations made during the load window. Fixed in iter 2 commit `ca8dfbf` by switching REPLACE → merge. See iter 2 entry above.

### WR-006: `compute_dest` falls back to `_inbox/invalid-source-basename` for empty/`.`/`..`

**Files modified:** `src-tauri/src/import_controller.rs`

**Commit:** `2db05a5`

**Applied fix:** Changed `compute_dest`'s return type from `PathBuf` to `Result<PathBuf, &'static str>`. Unusable basenames (`""`, `"."`, `".."`) now `Err("invalid source basename")` instead of silently routing to a fixed sentinel path. The single caller (`start_import_inner`) handles the `Err` by recording a per-file failure with the `invalid-name:` prefix, emitting an `error` status `import:progress` event, incrementing `failed`, and `continue`-ing the batch. `import-error.ts`'s W5 fallback (`extractRawTail`) handles the new prefix automatically — no new classifier branch needed. Pinned by two new module tests: `compute_dest_rejects_unusable_basenames` (parameterized over the 3 unusable basenames) and `compute_dest_happy_path_returns_expected_paths` (covers both course + non-_inbox and `None` + `_inbox` arms).
