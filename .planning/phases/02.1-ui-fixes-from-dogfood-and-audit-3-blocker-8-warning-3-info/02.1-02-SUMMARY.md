# Phase 02.1 Plan 02.1-02: B3 GREEN — claude_auth_check via subprocess probe Summary

Replaces the dogfood-killer `~/.claude/.credentials.json` existence probe with a `claude --version` subprocess invocation, closing the onboarding Step 2 blocker for fresh macOS Claude Code users (whose credentials live in the keychain, not the file). Wave 0's RED `inspector_keychain_detect` test is now GREEN.

## What Was Built

### Task 1 (commit `464c726`) — probe_claude_binary helper + claude_auth_check refactor

`src-tauri/src/lib.rs` L158-289 rewritten:

- **New pub fn `probe_claude_binary() -> ClaudeAuthStatus`** — pure sync helper invoking `std::process::Command::new("claude").arg("--version").output()` with the 4-arm match locked in CONTEXT D-02:
  - `Ok(success)` → `found=true, env_broken=false, version=parse_version_from_stdout(&stdout)`
  - `Ok(failure)` → `found=false, env_broken=false`
  - `Err(NotFound)` → `found=false, env_broken=false` (user hasn't installed claude yet — NOT a system break)
  - `Err(other)` → `found=false, env_broken=true` (WR-01 env_broken contract preserved)

- **New pub fn `parse_version_from_stdout(stdout: &[u8]) -> Option<String>`** — best-effort version literal extractor (first whitespace-separated token if it contains an ASCII digit or '.'); informational only, NOT load-bearing for the `found` gate.

- **claude_auth_check** refactored to a one-line `Ok(probe_claude_binary())` delegate. `#[tauri::command]` attribute + async signature preserved → Step2AuthCheck frontend continues to call `invoke<ClaudeAuthStatus>("claude_auth_check")` unchanged.

- **Old file-probe path fully removed** — `home::home_dir()` + `credentials.exists()` lines deleted. The `home::home_dir()` usages at lines 700 (vault_index DB path) and 799 (scratch dir setup) are unrelated and preserved.

- **Comment block rewritten (L158-211)** — documents WHY subprocess, WHY pure helper split, WHY no per-import overhead, WR-01 env_broken contract preservation, capability surface citation. The old "SPEC L121 forbids subprocess in step 2" paragraph deleted (D-02 explicitly reverses that constraint).

### Task 2 (commit `839c5ec`) — capability surface widening for `claude --version`

- **`src/lib/spawn-args.shared.ts`** — added `export const CLAUDE_VERSION_PROBE_ARGS = ["--version"] as const` with a header comment explaining the SSOT relationship to gen-capabilities.ts and the non-negotiable length-1 invariant.

- **`scripts/gen-capabilities.ts`** — imports `CLAUDE_VERSION_PROBE_ARGS`; maps it through the existing `escapeRegex` helper to build the `VERSION_PROBE_ARGS` validator array; appends a third entry `{ name: "claude-version-probe", cmd: "claude", args: VERSION_PROBE_ARGS }` to `SPAWN_ALLOW`. Because `SPAWN_ALLOW` is the source for both `shell:allow-spawn` and `shell:allow-execute`, the new entry appears in BOTH permission arrays automatically.

- **`src-tauri/capabilities/default.json`** — regenerated via `node --experimental-strip-types scripts/gen-capabilities.ts`. Net diff: +18 lines (one 9-line claude-version-probe block in each shell scope). Existing claude-bin-fresh / claude-bin-resume entries: byte-identical.

## Deviations from Plan

### [Rule 1 - Bug] tests/capability-regex.test.ts hard-coded the OLD 2-entry topology

**Found during:** Task 2 commit attempt.

**Issue:** The husky pre-commit hook ran `vitest --changed` and detected two failing structural-shape assertions in `tests/capability-regex.test.ts`:
- `has shell:allow-spawn permission with two allow entries (Option B dual Command names)` — `expect(scope.allow).toHaveLength(2)`
- `has shell:allow-execute permission mirroring the spawn topology (two entries)` — same length assertion

Both tests pinned the Plan 01-12 Option-B contract of exactly 2 chat-subprocess entries. Plan 02.1-02 deliberately introduces a third entry (`claude-version-probe`) per CONTEXT D-02 / Task 2, so these tests SHOULD update to reflect the new contract.

**Fix:** Updated both tests to expect 3 entries with the additional name `claude-version-probe`. Added a NEW describe block `claude-version-probe entry shape (B3 fix 02.1-02)` with 4 sub-tests pinning:
1. Single arg, validator literal `^--version$`.
2. Spawn-probe and execute-probe validator lists are byte-identical (mirrors the existing claude-bin-* invariant).
3. The validator regex rejects any other argv: `--bare`, `--version --bare`, `--version ; rm -rf /`, empty string, `-V`.
4. NO validator contains the string 'bare' (defense-vs-bypass invariant inherited from the chat-subprocess tests).

**Files modified:** `tests/capability-regex.test.ts` — 2 tests updated + 1 describe block (4 tests) added.

**Commit:** `839c5ec` (combined with the Task 2 main change — atomic because the test update is part of the same contract widening).

**Why combined commit (not separate test commit):** the SSOT contract widening (default.json +18 lines) and the test contract widening describe the SAME contract change. Separating them would leave the repo in a transient broken state between the two commits. The Rule 1 deviation is integral to the capability widening, not an orthogonal cleanup.
