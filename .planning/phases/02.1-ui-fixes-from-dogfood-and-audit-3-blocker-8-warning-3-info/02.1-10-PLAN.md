<objective>
Wave 2 polish — W4 (WARNING): per UI-REVIEW.md L41 + UI-SPEC §8.1.3, Step3VaultPicker should show a secondary ghost-link "Choose another folder" below the primary "Use this path" CTA. Currently the ONLY re-entry path for changing a Browse-chosen path is clicking the Browse button AGAIN, which is not communicated to the user once they've moved focus to "Use this path".

The fix: add `<button type="button" class="ghost-link" onclick={browse}>Choose another folder</button>` below the .cta, matching the Step 5 ghost-link pattern (per UI-REVIEW recommendation).

**Why ghost-link button (NOT span/anchor):** keyboard accessibility + Phase 2 focus-visible standard. A `<button>` element is tab-focusable by default; a `<span onclick>` is not. The "ghost-link" class strips button chrome (no background, no border) so it visually reads as a text link while preserving DOM semantics.

**Why execute (not TDD):** Pure additive markup + CSS styling. No state machine; no parameterized validation. Verification: grep + keyboard tab test.

**Why Wave 2:** Visual polish for re-entry discoverability; functional path already exists (clicking Browse again works). W4 closes the discoverability gap, not a functional gap.

**Out of scope:**
- Renaming "Use this path" / "Browse..." copy — locked.
- Adding undo / cancel / reset semantics — backlog.
- "Open in Finder" link — separate UI-SPEC §8.1.3 enhancement candidate, NOT 02.1.

**Parallel-safety (Wave 2):** Touches ONE file (`Step3VaultPicker.svelte`). No overlap with 02.1-07 / 08 / 09 / 11 / 12 / 13. All Wave 2 plans file-disjoint.
