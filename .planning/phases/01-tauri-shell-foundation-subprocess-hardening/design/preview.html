RAFT 用随机化超时是为了避免 split vote。如果两个 follower 在完全相同的 timeout 后转 candidate、同时给自己投票、再向集群广播 RequestVote，就会出现两边都拿不到 majority 的情况——term 增加、超时再触发、又同时转 candidate，循环里每个 election 都失败。

论文 §5.2 给的窗口是 [T, 2T] 上的均匀分布（典型 T = 150 ms）。两个 follower 都赶上同一 election cycle 的概率近似：

Pcollision ≈ Δt/T = RTT/T

当 RTT ≪ T（典型 LAN 是 1 ms / 150 ms ≈ 0.7 %），split vote 就以高概率被随机化打散，重选 1–2 轮就会收敛。

对照 deterministic backoff（比如 node-id 排序）：

// 反例 — deterministic：一台慢节点永远当不了 leader
timeout(node_id) = 150 + 30 * node_id  // ms
                 // node 0 → 150ms, node 1 → 180ms, ...

这种方案在不对称网络下会让低 id 的节点垄断 leadership，violates the symmetry-of-replicas property RAFT 要求的——所以 §5.2 显式选了 randomized。
