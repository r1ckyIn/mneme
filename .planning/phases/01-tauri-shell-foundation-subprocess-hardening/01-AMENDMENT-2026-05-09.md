### A-09 — Ctx + Session usage meter (replaces deleted cost meter)

**What:** Chat input header (above textarea, inside `.composer` block per Mneme.html L1395-1403) shows three pieces of info:
1. `Ctx 9.1%` — current context utilization percentage; reads `result.usage.input_tokens / model_context_window` (e.g., `200000` for default Sonnet 4.5; for Opus 4.7 1M = `1000000`).
2. Horizontal progress bar — width = `var(--cost-pct, 4%)`; CSS class repurposed to `.cost.warning` red state when ctx ≥ 90% (was: red when $-cap exceeded).
3. `Total · 18.2k` (cumulative tokens this session, format: `K`-suffix for thousands, `M`-suffix for millions) + `Session · 1h 24m` (rolling timer from first prompt; format: `Hh Mm` until 24h, then `Dd Hh`).

Phase 1 reads `result.usage.input_tokens` from each `result` event and persists `total_input_tokens` + `session_started_at` to a Svelte `$state` rune (no localStorage — rolls over on app restart per single-session semantics).

**Why:** User #5: "context token 和 session 持续时间的记录". Replaces the deleted $-cost surface (A-04). The CSS class name `.cost` is preserved for visual continuity with prototype (no rename needed); semantic meaning is now "ctx + session" not "$-cost". `.warning` state repurposed (red triggers when ctx ≥ 90%, not on $-overage).

**Source of truth:** Mneme.html L876-902 (CSS) + L1398-1403 (HTML).

**Impacted plans:** 01-06 (chat input header adds usage-meter component reading `result.usage.input_tokens` + session timer; replaces the deleted cost meter feature). New unit test: `tests/usage-meter.test.ts` — fixture `result` event with `usage.input_tokens=18200` + ctx_window=200000 → component renders "Ctx 9.1%, Total · 18.2k, Session · …" (timer mocked).
