# 01-12-PLAN — Session resume + chat-rendering hints + heading hierarchy (code-layer, dogfood gaps 2026-05-14)

## Objective

Close two related dogfood gaps surfaced 2026-05-14 by the user verifying the
shipped Phase 1 Tauri shell against the Claude.ai web mental model.

**GAP-1 — Session lifecycle mismatch (REQ-02 acceptance gap):** Every prompt
spawns a fresh `claude --print` subprocess; Claude has no memory of prior
turns in the same app session. Status dot also blinks grey between prompts
because `teardown()` calls `setStatus("disconnected")` on every subprocess
close (per-prompt natural close path), incompletely implementing the A-10
contract from 2026-05-09 amendment.

**GAP-2 — Output rendering doesn't match Claude.ai web (REQ-05 sanitize +
visual hierarchy gap):** Claude emits redundant ASCII fallbacks alongside
`$$...$$` math (CLI-default-prompt artifact); markdown headings h1/h2/h3 all
render at 16px/600 with no scale contrast; `<hr>` is invisible.

This plan ships behavioral fixes at four layers — Tauri capability topology
(spike-then-implement), spawn-args SSOT (optional opts arg), runtime wiring
(ChatPanel captures session_id and threads it into subsequent spawns), and
visual hierarchy (AssistantMessage CSS). Audit gates and capability JSON are
regenerated to honor the new flag surface. Phase 9 (REQ-17) is the
promotion path for full `--system-prompt` replacement; Phase 1 stays at
`--append-system-prompt`.

The .planning docs amendment (01-SPEC.md REQ-02/REQ-05 acceptance + REQUIREMENTS.md
traceability) is split into Plan 01-13 (wave 10, pure docs) per plan-checker H-3.

     appendSystemPrompt?: string;    // pinned to CHAT_RENDERING_HINTS at call site

     promptText: string,
     scratchDir: string,
     opts: BuildOpts = {},
   ): string[] {
     if (!new RegExp(SCRATCH_DIR_REGEX).test(scratchDir)) {
