## Hypotheses to test next session (in priority order)

### H1 — Tauri JS bridge not available in dev webview (most likely)
The `@tauri-apps/api/window` import may resolve to undefined in dev mode if
the Tauri bridge isn't injected, causing `startDragging()` to silently fail
in the catch block. Test:
```js
// in Mneme devtools console (Cmd+Opt+I):
window.__TAURI_INTERNALS__   // should be an object
window.__TAURI__             // legacy reference
const { getCurrentWindow } = await import("@tauri-apps/api/window");
getCurrentWindow().startDragging();   // does this work directly?
```
If `__TAURI_INTERNALS__` is undefined, the bridge isn't injected — that's
a Tauri 2 webview config issue. Check `tauri.conf.json` for `app.withGlobalTauri`
or whether the build is loading the wrong entry.

### H2 — HMR de-armed the listener
The onMount cleanup runs but the addEventListener bound a fresh listener;
maybe a HMR cycle removed +page.svelte and re-mounted, but Tauri's native
mousedown injection persisted in a stale state. Test:
- Stop dev server entirely, full `cargo clean && npm run tauri dev`, then
  test drag on a brand-new webview boot.

### H3 — `decorations:true + titleBarStyle:Overlay + hiddenTitle:true`
combination is known to be flaky on Tauri 2 / macOS. Some Tauri issues
suggest using `decorations: false` + custom traffic-light DOM (the
prototype's pattern) actually works better because the webview owns the
entire surface. Test:
- Try `decorations: false` in tauri.conf.json
- Restore the `.traffic-lights` DOM from prototype (it was correct in this
  case — the bug was that we had BOTH OS dots and DOM dots). With
  decorations: false, only the DOM dots show.
- Apply `data-tauri-drag-region` to titlebar; verify drag works.

### H4 — `tauri.conf.json` is missing some required permission/capability
for window dragging. Check `src-tauri/capabilities/default.json` (it's
the audit-locked file from plan 01-02). Specifically look for
`core:window:allow-start-dragging` permission. If missing, add it via
`scripts/gen-capabilities.ts` (do NOT hand-edit `default.json` — the audit
script will fail).
