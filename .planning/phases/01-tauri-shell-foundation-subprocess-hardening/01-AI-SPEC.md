## 1. System Classification

**System Type:** Conversational + Code Automation hybrid

**Description:**
mneme is a single-user (the developer) macOS desktop learning app whose right-hand pane is a **Tauri 2 shell wrapping the Claude Code CLI as a managed subprocess**. The CLI is a code-aware autonomous agent (MCP, file tools, agentic search via `--add-dir`) — Phase 1 wires only the **first session** end-to-end: prompt input → spawn → stream-json events parsed → finalized markdown + KaTeX rendered with DOMPurify-sanitized HTML on `result`. "Good" in this phase = a session can run, stream legibly, render math safely, kill cleanly on Cmd+Q, and refuse to spawn under wildcard / unscoped capability conditions. The user is also the only "domain expert" — there is no separate stakeholder population.

**Critical Failure Modes:**
1. **Orphaned grandchildren after Cmd+Q.** Claude CLI calls `setsid()`; `child.kill()` only kills the PID, leaving MCP / `grep` / `read` grandchildren alive — RAM and battery silently leak across days. Closure: `libc::killpg(getpgid(pid), SIGTERM)` → 2s → `SIGKILL`; verified by `ps aux | grep claude` after 5 quit cycles.
2. **Streaming markdown XSS.** A model-generated `<img src=x onerror=...>` or `$\href{javascript:alert()}{x}$` reaching the WebView during the chunky→finalized switch executes JS in the Tauri context (full file-system reach). Closure: DOMPurify with explicit `FORBID_TAGS` + `FORBID_ATTR`, KaTeX `trust:false strict:true macros:{} maxExpand:1000`, KaTeX error message HTML-escaped, CSP meta tag.
3. **Capability wildcard / SSOT drift.** Any `"*"` or `"args": true` in `src-tauri/capabilities/default.json` lets the WebView spawn any binary with any args (file exfiltration / arbitrary exec). Drift between the TS spawn-args SSOT and the Rust capability JSON re-opens the same hole. Closure: ~13 exact-regex per-arg validators, `scripts/audit-capabilities.sh` running `diff` between TS gen-output and committed JSON, plus `grep -c '"args": true'` and `grep -c '"\*"'`.
4. **Cost / loop runaway under OAuth subscription.** No per-call billing means the only structural guard against an infinite tool-use loop is `--max-turns 30` on every spawn. A stuck agent without this cap can drain rate-limit budget for the rest of the day. Closure: `--max-turns 30` is part of the locked spawn-args SSOT (`src/lib/spawn-args.ts`); audit script greps for its presence.
5. **`--add-dir` scope leak.** REQ-10 requires agentic search default-on, scoped to `~/.mneme/scratch/` only. If `--add-dir` is missing or wildcards (`/`, `~`), the agent reads anywhere on the FS — privacy + KP-01 local-first violation. Closure: `--add-dir <SCRATCH>` is non-optional in spawn-args SSOT; capability validator regex pins it to the literal scratch path.

## 1b. Domain Context

> Researched by `gsd-domain-researcher`. Grounds the evaluation strategy in domain expert knowledge.

**Industry Vertical:** Personal developer tooling / single-user desktop AI client (CS undergraduate self-study domain — University of Sydney). **Not a typical commercial vertical** — there is no end-customer population, no compliance reviewer, no enterprise stakeholder. Treat the term "domain" loosely: the closest analog is "developer tooling + desktop AI client safety" (the bar a careful developer applies to a Tauri-shelled CLI wrapper that holds OAuth credentials and FS reach).

**User Population:** **Exactly one user — the developer** (CS undergraduate at University of Sydney, primary languages Python / Java / JavaScript / Go, located Sydney AU, on macOS Ventura 13.4 / Intel Mac per `r1ckyIn_GitHub/CLAUDE.md`). No second-tier users in v1. Distribution is explicitly out-of-scope (REQUIREMENTS.md OOS). The aspirational future-user population — "future students with similar workflow" — is **NOT** in v1 scope and must not be projected into Phase 1's stakes calculus. Per PROJECT.md RQ-05 ("learning-method epistemic humility"), all 18 of mneme's REQs derive from an n=2 sample of higher-achieving students; this is a known epistemic limit, but it does not create a Phase-1 stakeholder.

**Stakes Level:** **HIGH** (one-user blast radius, no third-party data). Not Critical. Concrete stakes ceiling:
- XSS in the Tauri WebView = full filesystem reach via the Tauri IPC surface (`@tauri-apps/api/fs`, `tauri-plugin-shell`).
- Capability-scope leak = vault exfiltration via a malicious model output that smuggles `\href{...}` or `<img onerror=...>` past the sanitizer, or convinces the agent to spawn an out-of-scope binary.
- Subprocess-zombie leak = day-by-day RAM and battery drain (no money loss, but the user notices).
- Loop runaway under OAuth subscription = full-day rate-limit exhaustion (no per-call dollar cost, but the user is locked out of Claude until reset).

What KEEPS this from being Critical: no PII, no PHI, no financial data, no third-party data, no telemetry pipe, no distribution surface, no second user whose data can leak. Blast radius is bounded to the developer's own machine and own subscription.

**Output Consequence:** Phase 1's "AI output" is **NOT the user-facing chat answer** (that's evaluated in Phases 6/7/9/10). Phase 1's "output" is mostly mechanical: did the subprocess die cleanly on Cmd+Q? Did finalized markdown render without executing JS? Did the capability layer reject a wildcard? Did `--max-turns 30` actually cap the agent loop? **Phase 1 hardens the BLAST RADIUS that every later phase will operate inside** — if v1 ships with a wildcard `"args": true` capability or unsanitized HTML, Phase 2's vault writes and Phase 6's Echo360 webview cookies become attack surfaces against an attacker who controls model output. Per CONTEXT.md L9, the delivery threshold is "`npm run tauri dev` runnable, all CRITICAL pitfalls (zombies, cost runaway, XSS, capability wildcards) closed **before user starts dogfooding**".

### What Domain Experts Evaluate Against

> N=1 — the "domain expert" IS the user. Rubric ingredients are expressed in the developer's own evaluation language, drawn from spike-002 dogfood + SPEC acceptance criteria + CONTEXT.md decisions. No commercial-vertical jargon.

**Dimension: Streaming legibility**
Good (developer accepts): First text appears within ~2-4s TTFT (network → Anthropic → first `text_delta`); chunky monospace `<pre>` updates smoothly during stream; on `result` + `close`, finalized markdown structurally matches what was streamed (paragraphs, code fences, lists all intact). KaTeX math renders inline (`\frac{a}{b}`) and display (`$$...$$`) correctly.
Bad (developer flags): Long blank wait (>6s with no system bubble explaining why); reflow flickers when monospace → markdown switch happens; finalized markdown breaks because partial code fences were promoted to HTML mid-stream.
Stakes: Low (UX irritation; not safety).
Source: spike-002 dogfood, spike-findings tauri-shell-ui.md §4 ("stream raw monospace, finalize on `result` only").

**Dimension: Subprocess cleanliness**
Good: After 5 spawn → Cmd+Q cycles, `ps aux | grep "[c]laude --print"` returns 0 rows and `ps aux | grep -E "[m]cp|[r]ipgrep|[g]rep --color"` shows no orphaned grandchildren attributable to mneme.
Bad: Any orphan still alive 2 seconds after `RunEvent::ExitRequested` fires; any leaked PID accumulating across multiple launches.
Stakes: HIGH (battery / RAM drain across days, plus the developer must trust the app to release resources before they'll keep it always-running).
Source: SPEC REQ-3 + CONTEXT.md D-10 (`killpg(getpgid(pid), SIGTERM)` → 2s → `SIGKILL`).

**Dimension: Math + code rendering safety**
Good: KaTeX configured with `trust:false strict:true macros:{} maxExpand:1000` renders standard LaTeX correctly; `\href{javascript:alert(1)}{x}` does NOT execute (KaTeX silently strips or HTML-escapes the JS URL); `<img src=x onerror=alert(1)>` in model output does not execute (DOMPurify runs after `marked.parse` with explicit `FORBID_TAGS` + `FORBID_ATTR`); KaTeX render-error messages are HTML-escaped before display so they cannot themselves carry XSS; CSP meta tag is present in `app.html`.
Bad: Any `alert()` triggers from a model-emitted payload during dev test; KaTeX `\macroexpand` infinite loop hangs the WebView; raw `<script>` tag survives into rendered DOM.
Stakes: HIGH (XSS in Tauri WebView = full FS reach via IPC; one of the three CRITICAL Phase-1 pitfalls).
Source: SPEC REQ-5 + spike-findings tauri-shell-ui.md §4 + KaTeX security advisory (`trust:false` is the default in v0.16.21+ but explicit-set is required to defend against config drift).

**Dimension: Capability scope discipline**
Good: `src-tauri/capabilities/default.json` contains zero `"*"` (verified by `grep -c '"\*"'` returning 0), zero `"args": true` (verified by `grep -c '"args": true'` returning 0); every spawn-arg has a corresponding exact-regex validator (~13 entries, alternating between flag-literal regex like `^--add-dir$` and value regex like `^/Users/[^/]+/\.mneme/scratch$`); `scripts/audit-capabilities.sh` blocks the PR if `diff <(node scripts/gen-capabilities.ts --dry-run) src-tauri/capabilities/default.json` is non-empty (i.e., SSOT drift between `src/lib/spawn-args.ts` and committed JSON).
Bad: Any wildcard accepted in default.json; any drift between TS SSOT and Rust capability JSON; any capability entry that allow-lists `bash` / `curl` / `python` / `node` (anything other than `claude-bin`).
Stakes: HIGH (capability leak = WebView can ask the shell plugin to spawn arbitrary binaries with arbitrary args; one of the three CRITICAL Phase-1 pitfalls).
Source: SPEC REQ-4 + CONTEXT.md D-14 (TS SSOT) + D-15 (declarative-only — no Rust runtime builder available).

**Dimension: Tool-use round-trip clarity**
Good: When the `claude` agent calls Read / Bash / Grep / WebFetch / etc., the chat panel shows a distinct collapsed tool-use card — name + truncated input (≤200 chars) on the request side, distinct card for `tool_result` on the response side. Cards are visually separable from assistant text bubbles. The text-block of an assistant turn is NOT double-rendered (already streamed via `stream_event`; consolidated `assistant` event must skip `block.type === "text"` to avoid duplication).
Bad: Tool calls disappear into the stream; raw JSON is splatted into the message; finalized markdown is corrupted because tool-use input/output JSON broke a code fence; assistant text appears twice.
Stakes: Medium (the developer needs to debug what the agent did across a 30-turn loop; opacity here drives the "what just happened" frustration).
Source: spike-002 tool-use card pattern, spike-findings claude-subprocess.md §5.

**Dimension: Loop-runaway protection**
Good: Every `claude` spawn passes `--max-turns 30`; CI / pre-commit grep confirms presence in `src/lib/spawn-args.ts` (`grep -F '"--max-turns"' src/lib/spawn-args.ts && grep -F '"30"' src/lib/spawn-args.ts`). After a forced infinite-loop test (e.g., a prompt that asks the agent to recurse), the session terminates at turn 30 with `stop_reason: "max_turns"` in the `result` event; rate-limit budget is preserved.
Bad: Spawn args list omits `--max-turns`; a session can recurse beyond 30 turns; rate-limit budget is exhausted on a single runaway loop.
Stakes: HIGH (rate-limit drain locks the user out of Claude for the rest of the day; the only structural ceiling under OAuth subscription billing where there is no per-call dollar cost to slow down a runaway).
Source: critical failure mode #4 (Section 1, AI-SPEC.md) + SPEC REQ-2 + CONTEXT.md spawn-args SSOT.

**Dimension: Vault scope leak protection**
Good: `--add-dir` argument is exactly `${HOME}/.mneme/scratch` in Phase 1; capability validator regex pins the value to `^/Users/[^/]+/\.mneme/scratch$`; agentic search results (verified via dev-console log of `result.usage` + `tool_use` cards) never reference paths outside the scratch directory; `~/.mneme/scratch/` is auto-created on first launch.
Bad: `--add-dir` missing entirely (agent can't search) OR `--add-dir` set to `/`, `~`, or any user-writable parent (agent can read anywhere on FS); a `tool_use` Read/Glob call references a path outside scratch.
Stakes: HIGH (KP-01 local-first violation: a malicious model output could exfiltrate vault contents, dotfiles, SSH keys, or browser cookies via WebFetch + Read; this is the highest-stakes failure mode bounded to a single user).
Source: REQ-10 + critical failure mode #5 (Section 1, AI-SPEC.md) + CONTEXT.md spawn-args SSOT.

### Known Failure Modes in This Domain

> mneme-specific failure modes drawn from spike-001 / spike-002 dogfood + spike-findings + Tauri / Claude CLI documented gotchas. Not generic "AI hallucinates" — each is a concrete failure observed or predicted in the developer-tooling-around-Claude-CLI domain.

1. **Subprocess zombies after Cmd+Q on macOS** — the `claude` CLI calls `setsid()` to detach its child process group (so it can spawn MCP servers, ripgrep, grep, file_read as long-lived grandchildren). `child.kill()` from `@tauri-apps/plugin-shell` and `CommandChild::kill()` in Rust both send a single signal to the *PID*, not the *PGID* — leaving every grandchild alive. After 5 quit cycles, `ps aux` shows 5+ orphaned `mcp` / `ripgrep` processes consuming RAM. Mitigation: `nix::sys::signal::killpg(getpgid(pid), SIGTERM)` → 2s → `SIGKILL`. (CONTEXT.md D-10, D-11; SPEC REQ-3.)

2. **`--bare` flag silently breaks OAuth subscription auth** — adding `--bare` to spawn-args strips the keychain reads that the OAuth Pro/Max session needs. The subprocess returns instantly with empty stdout and exit code 0 — no error message, no failure log, the chat panel just shows "stream ended unexpectedly". Mitigation: `--bare` MUST be absent from `src/lib/spawn-args.ts`; `audit-capabilities.sh` greps for the literal string `bare` and fails CI on any match. (Spike F4/F6, spike-findings claude-subprocess.md "What to Avoid".)

3. **Line-buffer reset bug — long lines split across `data` events break `JSON.parse`** — the `cmd.stdout.on("data")` callback fires per byte chunk, not per JSON event line. A single chunk may contain (a) one complete line, (b) two complete lines, (c) one complete line plus a partial line, or (d) a fragment of one line. Naively running `JSON.parse(chunk)` throws randomly mid-stream and kills the dispatch loop. Mitigation: accumulate into a `let buffer = ""`, split on `\n`, `buffer = parts.pop() ?? ""` to retain the unfinished tail, then `JSON.parse` each non-empty complete line in a try/catch (drop malformed lines silently). (Spike-findings claude-subprocess.md §3, AI-SPEC §3 common pitfall #3.)

4. **DOMPurify invoked BEFORE `marked.parse` silently no-ops on the markdown source** — `marked` emits HTML strings (`<table>`, `<pre><code>`); sanitizing the markdown source before parse passes through inert text without sanitizing, AND breaks code fences and tables in the parsed output. The XSS gap is invisible until a payload trips it. Mitigation: `sanitize.ts` exposes `sanitizeMarkdown(text)` that internally calls `DOMPurify.sanitize(marked.parse(text), {FORBID_TAGS: [...], FORBID_ATTR: [...]})` — DOMPurify always runs AFTER marked.parse, on the HTML output. KaTeX is a separate site: `katex.renderToString → DOMPurify.sanitize → DOM injection`. (Spike-findings tauri-shell-ui.md §4, AI-SPEC §3 common pitfall #5.)

5. **Tauri capability JSON drift from TypeScript spawn-args SSOT** — `src/lib/spawn-args.ts` is the source of truth for which `claude` args are legal; `src-tauri/capabilities/default.json` is the runtime enforcement. If a developer adds a new arg to `spawn-args.ts` but forgets to regenerate `default.json` (or hand-edits one without the other), the spawn fails at runtime — OR worse, an old capability entry with a wildcard remains and the new arg passes through unchecked. Mitigation: `scripts/gen-capabilities.ts` is a `prebuild` hook that derives `default.json` from `spawn-args.ts`; `scripts/audit-capabilities.sh` runs `diff <(node scripts/gen-capabilities.ts --dry-run) src-tauri/capabilities/default.json` and fails CI on non-empty diff, plus `grep -c '"args": true'` and `grep -c '"\*"'`. (CONTEXT.md D-14, D-15; SPEC REQ-4.)

6. **KaTeX `trust:true` (or any `\href` permitting macros) accepts `\href{javascript:alert(1)}{x}`** — KaTeX v0.16.21+ defaults to `trust:false`, but old code may have explicit-set `trust:true` and forgotten to revert. Even with `throwOnError:false`, the rendered MathML/SVG can carry a JS URL via `\href`. Custom `macros:{...}` config can also register macros that bypass the trust check. Mitigation: `katex.renderToString(src, {trust:false, strict:true, macros:{}, maxExpand:1000, throwOnError:false})` — all four guards together. The `e.message` from a render error MUST be passed through `escapeHtml()` before display, since KaTeX error messages quote the offending source verbatim. (Spike-findings tauri-shell-ui.md §4, AI-SPEC §3 common pitfall #6.)

## 2. Framework Decision

**Selected Framework:** Claude Code CLI subprocess (via `tauri-plugin-shell` sidecar; `CommandChild` + `tauri::State<Mutex<Option<CommandChild>>>` Rust state machine per CONTEXT.md D-10)

**Version:** Claude Code CLI — user-installed via OAuth subscription (no version pin in mneme repo; CLI self-updates). `tauri-plugin-shell` v2.x (Tauri 2 stable). `vendor/claude-code-parser/` — frozen reference snapshot at upstream commit on 2026-05-08 per KD-12 + D-13 (do NOT `npm install` — copyleft of upstream maintenance, not licensing).

**Rationale:**
The `claude` CLI **is** the agent runtime — mneme's job is to be a clean execution boundary around it. Three reasons this beats every "AI framework" in `ai-frameworks.md`:

1. **OAuth subscription billing (KP-04)** is incompatible with API-key SDKs (Claude Agent SDK, claude-code-sdk-ts, LangChain/LlamaIndex/CrewAI/LangGraph). Subscribing once and paying $0 per call is the entire economic premise of mneme; a framework that forces API-key mode is a non-starter.
2. **Phase 1's three CRITICAL pitfalls (zombies / capability wildcards / streaming XSS)** all live AT the subprocess + IPC + WebView capability boundary. SDKs abstract that boundary away. Spike-002 validated that the subprocess + stream-json pattern exposes exactly the layers that need hardening.
3. **MCP, agentic search, file tools, hooks** are already built into the CLI. No "agent orchestration framework" we'd add could improve on what Anthropic ships in the CLI itself; we'd just be re-implementing it badly.

**Alternatives Considered:**

| Framework | Ruled Out Because |
|-----------|------------------|
| Claude Agent SDK (TypeScript, Anthropic) | Forces API-key billing → breaks KP-04 OAuth subscription model. Abstracts away the subprocess + capability layer that REQ-3 / REQ-4 / REQ-5 explicitly engineer. |
| `claude-code-sdk-ts` (community, MIT) | Delegates auth to CLI but does NOT spawn a subprocess (it pipes through CLI under the hood without exposing `CommandChild`). Cannot satisfy REQ-3 lifecycle / D-10 PGID kill — those need direct subprocess control. |
| JSONL file-tail pattern (`markes76/claude-code-gui` MIT) | Reads `~/.claude/projects/*.jsonl` after-the-fact instead of spawning. Loses spawn-arg control (`--max-turns`, `--add-dir`, `--exclude-dynamic-system-prompt-sections`) that REQ-2 + REQ-10 + critical failure mode #4 require. Useful as **mental fallback** if subprocess pattern ever breaks; not as primary. |
| LangChain / LlamaIndex / CrewAI / LangGraph / OpenAI Agents SDK | Wrong layer entirely — we already have an agent (the CLI). These would replace the CLI, not host it. Plus all force API-key mode. |
| Embed a local LLM (`llama.cpp` + quantized 8B) | Intel Mac CPU inference too slow per STACK.md. Deferred until Apple Silicon hardware refresh. Would also lose Claude's tool-use / MCP ecosystem. |

**Vendor Lock-In Accepted:** **Yes — intentionally.** Per OOS-08 (single LLM provider) + KP-04 (OAuth subscription), Anthropic vendor lock is a **deliberate** choice for v1: the developer already pays for Claude Pro/Max, and supporting multiple providers would force API-key mode and add eval-tooling complexity disproportionate to a single-user app. Migration path documented for v2+: if Anthropic changes terms or we need provider-agnostic deployment, swap the subprocess from `claude` to a provider-agnostic CLI (e.g., a future `aider`-style multi-model runner) — the Tauri shell + capability hardening + render pipeline are provider-independent.

### Core Imports

```typescript

// src/routes/+page.svelte — chat panel core (right column of three-pane layout per D-02).
// REPLACES the unbounded spike-002 invocation. ~50-line backbone shown; D-19 Stop button + D-20
// Shift+Enter handling layered on top in the Phase 1 fresh write.
import { Command } from "@tauri-apps/plugin-shell";
import { invoke } from "@tauri-apps/api/core";
import { buildClaudeArgs } from "$lib/spawn-args";
import { dispatchEvent } from "$lib/stream-dispatch";    // 6-event handler from spike-findings §4

let prompt = $state("");
let messages = $state<Msg[]>([]);
let isStreaming = $state(false);

async function sendPrompt() {
  if (!prompt.trim() || isStreaming) return;
  isStreaming = true;

  // 1. Spawn — capability layer enforces ~13 per-arg regex; no `--bare` allowed.
  const cmd = Command.create("claude-bin", buildClaudeArgs(prompt.trim()));
  let buffer = "";

  // 2. Line-buffer stdout — chunks ≠ event lines (spike-findings §3, common pitfall #3).
  cmd.stdout.on("data", (chunk: string) => {
    buffer += chunk;
    const parts = buffer.split("\n");
    buffer = parts.pop() ?? "";                          // keep partial last line
    for (const raw of parts) {
      if (!raw.trim()) continue;
      try { dispatchEvent(JSON.parse(raw), messages); }   // 6-event taxonomy
      catch { /* malformed line — ignore, never throw mid-stream */ }
    }
  });

  // 3. `result` is the ONLY reliable session terminator (spike-findings §6, common pitfall #4).
  //    `close` fires after `result`; finalize render here.
  cmd.on("close", () => {
    isStreaming = false;
    requestAnimationFrame(() => {
      document.querySelectorAll(".bubble.assistant")
        .forEach((el) => renderMath(el as HTMLElement));   // KaTeX walk + DOMPurify
    });
  });

  // 4. Hand the PID to Rust so Cmd+Q can do PGID kill (D-10 — child.kill() alone leaks grandchildren).
  const child = await cmd.spawn();
  await invoke("register_session_pid", { pid: child.pid });
  prompt = "";
}
```

```rust
// src-tauri/src/lib.rs — Rust state machine (D-10). The CommandChild is conceptually
// owned by Rust; the frontend hands the PID over via `register_session_pid`.
// TWO hooks union — macOS Cmd+Q dispatches RunEvent::ExitRequested, NOT WindowEvent::CloseRequested.
struct SessionState(Mutex<Option<u32>>);                  // single-session per Phase 1 / D-10

#[tauri::command]
fn register_session_pid(state: State<SessionState>, pid: u32) {
    *state.0.lock().unwrap() = Some(pid);
}

fn kill_pgid(pid: u32) {
    let pid = Pid::from_raw(pid as i32);
    if let Ok(pgid) = getpgid(Some(pid)) {
        let _ = killpg(pgid, Signal::SIGTERM);
        std::thread::sleep(std::time::Duration::from_secs(2));
        let _ = killpg(pgid, Signal::SIGKILL);              // SIGKILL only if still alive
    }
}

#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
    tauri::Builder::default()
        .plugin(tauri_plugin_shell::init())
        .manage(SessionState(Mutex::new(None)))
        .invoke_handler(tauri::generate_handler![register_session_pid])
        .on_window_event(|_w, e| {
            if matches!(e, WindowEvent::CloseRequested { .. }) { /* trigger kill */ }
        })
        .build(tauri::generate_context!())
        .unwrap()
        .run(|app, e| {
            // Cmd+Q on macOS — see Tauri issue #9198 for the union rationale.
            if matches!(e, RunEvent::ExitRequested { .. }) {
                if let Some(pid) = app.state::<SessionState>().0.lock().unwrap().take() {
                    kill_pgid(pid);
                }
            }
        });
}
```

### Common Pitfalls

> Six pitfalls from spike-findings + `claude` CLI behavior. Each is paired with a concrete closure in this phase's REQs.

1. **`--bare` is incompatible with OAuth subscription auth — DO NOT add it to `spawn-args.ts`.** Spike F4/F6 (`spike-findings/references/claude-subprocess.md` "What to Avoid"): `--bare` strips the keychain reads that the OAuth-Pro/Max session relies on; the subprocess returns instantly with no output and no error. Save *cost* by adding `--exclude-dynamic-system-prompt-sections` instead (~107k → <20k cache_creation tokens; spike-findings §7 / SPEC acceptance criterion). **Closure**: `--bare` is *absent* from `spawn-args.ts` SSOT; `audit-capabilities.sh` fails on any capability validator regex containing the literal string `bare`.

2. **`Command.kill()` (frontend) and `CommandChild.kill()` (Rust) only kill the PID, not the process group.** The `claude` CLI calls `setsid()` and spawns MCP servers / `grep` / `read` as grandchildren. After Cmd+Q those grandchildren survive — RAM + battery silently leak across days. **Closure**: D-10 frontend-spawns and hands the PID to Rust; Rust runs `nix::sys::signal::killpg(nix::unistd::getpgid(Pid::from_raw(pid)), SIGTERM)` → 2s wait → `SIGKILL`. SPEC acceptance: `ps aux | grep "[c]laude --print"` returns 0 rows after 5 quit cycles.

3. **stdout `data` events are byte chunks, not event lines.** A single `cmd.stdout.on("data")` callback can fire mid-line; conversely, multiple JSON events can arrive in one `data` event. `JSON.parse(chunk)` will throw randomly. **Closure**: line-buffering pattern from spike-findings §3 — accumulate into `buffer`, split on `\n`, `buffer = parts.pop()` to retain the unfinished tail, `JSON.parse` each non-empty complete line in a try/catch.

4. **`result` is the ONLY reliable session terminator — never finalize on `assistant` or on stream-end heuristics.** A multi-turn tool-use loop emits multiple `assistant` events interleaved with `user` (tool_result) events. `cmd.on("close")` is also unreliable: claude may emit `result` and stay alive briefly while the parser flushes; conversely, network errors can close the pipe with no `result`. **Closure**: drive the "finalize markdown + KaTeX render" hook off `cmd.on("close")` AFTER having received a `result` event; if `close` fires without `result`, surface a system-bubble error and skip finalization (spike-findings §4 + §6).

5. **DOMPurify must run AFTER `marked.parse`, not before.** marked emits raw HTML strings (e.g. `<table>`, `<pre><code>`); sanitizing the markdown source before parse breaks code fences and tables. **Closure**: `sanitize.ts` exposes `sanitizeMarkdown(text)` that internally calls `DOMPurify.sanitize(marked.parse(text), {FORBID_TAGS: [...], FORBID_ATTR: [...]})`. KaTeX is a separate site — render text → `katex.renderToString()` → `DOMPurify.sanitize` → DOM injection (spike-findings tauri-shell-ui.md §4 + REQ-5).

6. **KaTeX `trust:true` (the default) lets `\href{javascript:alert()}{x}` execute.** Even with `throwOnError:false` the rendered MathML/SVG can carry a JS URL via `\href`. `trust:true` is the explicit signal-of-intent for trust-mode macros; `strict:false` allows non-strict commands; an empty `macros:{}` is required because user `macros` config can register custom macros that bypass `trust`. **Closure** (REQ-5): `katex.renderToString(src, {trust:false, strict:true, macros:{}, maxExpand:1000, throwOnError:false})`. The `e.message` from a render error MUST be passed through `escapeHtml()` before display — KaTeX error messages quote the offending source verbatim and themselves can carry HTML.

## 4. Implementation Guidance

**Model Configuration:**

Model selection is **delegated to the `claude` CLI** — mneme's spawn layer exposes no temperature / top_p / max_tokens controls. The CLI internally selects the model based on the user's OAuth subscription tier (Pro / Max) and its own `~/.claude/settings.json`. The only model-adjacent budget mneme owns is the agent-loop depth cap:

| Parameter | Value | Owner | Purpose |
|-----------|-------|-------|---------|
| `--max-turns` | `30` | mneme `spawn-args.ts` | Tool-use loop cap (critical failure #4 closure). Hard guard against infinite tool-use under OAuth (no per-call billing means rate-limit budget is the only ceiling). |
| `--add-dir` | `~/.mneme/scratch` | mneme `spawn-args.ts` | FS scope for agentic search (REQ-10 + critical failure #5). Phase 2 swaps in user-configured vault path via REQ-14 settings. |
| `--exclude-dynamic-system-prompt-sections` | (flag) | mneme `spawn-args.ts` | Trims auto-prepended planning/state context. Drops first-call cache_creation_input_tokens from ~107k (spike-findings cost-reality) to <20k (REQ-2 acceptance). |
| `temperature` / `top_p` / `max_tokens` | (not set) | `claude` CLI internal | Not exposed; mneme does not touch them in Phase 1. Phase 9 (anchored mode) may add a custom system prompt; even then per-token sampling stays inside the CLI. |
| Model name | (not pinned) | `claude` CLI internal | Phase 1 logs `system.init.model` to dev console for visibility, never pins or overrides. |

**Core Pattern:**

The end-to-end loop is a **single-producer / two-consumer pipeline**:

- **Producer**: the `claude` subprocess emits NDJSON to stdout.
- **Consumer A** (frontend, hot path): line-buffer + JSON.parse + 6-arm dispatch → Svelte 5 `$state` mutation → reactive re-render of monospace `<pre>` during stream.
- **Consumer B** (frontend, cold path on `cmd.on("close")` after `result`): walk all `.bubble.assistant` nodes, replace text with `marked.parse → DOMPurify` HTML, then DOM-walk for `$...$` / `$$...$$` and replace each with `katex.renderToString → DOMPurify`.
- **Lifecycle owner** (Rust): holds `Mutex<Option<u32>>` (the spawned PID). On `WindowEvent::CloseRequested` ∪ `RunEvent::ExitRequested`, runs `nix::killpg(getpgid(pid), SIGTERM)` → 2s wait → `SIGKILL`.

```typescript
// src/lib/stream-dispatch.ts — the 6-event hot path. Pure function over (evt, messages),
// no side effects beyond pushing to the messages array. Spike-findings §4 typing.
import type { StreamEvent } from "$vendor/claude-code-parser";

export function dispatchEvent(evt: StreamEvent, messages: Msg[]): void {
  switch (evt.type) {
    case "system":
      // Suppress all except subtype="init" (session-start indicator). NEVER render hooks/status.
      if (evt.subtype === "init") {
        console.log(`[claude:init] model=${evt.model} cwd=${evt.cwd}`);  // D-18 dev-console only
      }
      break;

    case "stream_event": {
      // Primary streaming consumer — Anthropic SSE per-token deltas live inside `evt.event`.
      const inner = evt.event;
      if (inner?.type === "content_block_delta" && inner.delta?.type === "text_delta") {
        const m = ensureAssistantMsg(messages);
        m.text += inner.delta.text;
        // Svelte 5 reactivity trigger — caller does `messages = [...messages]` after this returns.
      }
      // ttft_ms lives on the FIRST stream_event of the session (spike-findings §7).
      if (typeof evt.ttft_ms === "number") console.log(`[claude:ttft] ${evt.ttft_ms} ms`);
      break;
    }

    case "assistant": {
      // Consolidated turn — iterate content blocks for tool_use + thinking only.
      // text blocks are ALREADY streamed via stream_event; do not re-append (would double-render).
      for (const block of evt.message?.content ?? []) {
        if (block.type === "tool_use") {
          messages.push({ role: "tool", text: `${block.name}: ${JSON.stringify(block.input).slice(0, 200)}`, ... });
        } else if (block.type === "thinking") {
          // Encrypted in `signature` for OAuth users — render indicator ONLY (spike-findings §5).
          messages.push({ role: "system", text: "💭 thinking...", ... });
        }
      }
      break;
    }

    case "user": {
      // Tool result round-trip (REQ-2 round-trip rendering).
      const content = evt.message?.content?.[0];
      if (content?.type === "tool_result") {
        messages.push({ role: "tool", text: stringifyToolResult(content.content), ... });
      }
      break;
    }

    case "rate_limit_event":
      console.log(`[claude:rate-limit]`, evt);                    // D-18 dev-console only
      break;

    case "result":
      // END marker — captures final cost/duration/usage. The `close` handler triggers finalization.
      console.log(`[claude:result] cost=$${evt.total_cost_usd} dur=${evt.duration_ms}ms ` +
                  `cache_creation=${evt.usage?.cache_creation_input_tokens}`);
      break;
  }
}
```

**Tool Use:**

The `claude` CLI ships with built-in tools (`Bash`, `Read`, `Glob`, `Grep`, `Edit`, `Write`, `WebFetch`, `WebSearch`, MCP servers, etc.) that are **automatically available** — mneme does not configure, register, or restrict them via spawn args in Phase 1. Tool-use round-trip rendering follows spike-findings §5: an `assistant` event with `block.type === "tool_use"` precedes a `user` event with `block.type === "tool_result"`; both render as collapsed tool cards in the chat panel.

**Phase 1's tool-use safety boundary lives at the *binary spawn* layer, not the *internal tool* layer:**

- The Tauri capability scope (REQ-4) restricts what binaries the *WebView* can ask `tauri-plugin-shell` to spawn — exactly one allow-listed entry: `claude-bin → claude --print --permission-mode bypassPermissions ...` with ~13 exact-regex per-arg validators. The WebView cannot ask the shell plugin to spawn `bash`, `curl`, `python`, or *any* other binary.
- The `claude` CLI, once spawned, can internally call `Bash` / `WebFetch` / etc. These calls DO NOT route through the Tauri capability layer — they happen inside the `claude` process via direct OS calls. The `--permission-mode bypassPermissions` flag is what permits these (without it, the CLI's interactive permission prompts hang in piped non-interactive mode).
- This is a **deliberate Phase-1 scope choice**: REQ-4 hardens the WebView↔OS boundary; the CLI↔OS boundary is delegated to Anthropic's CLI for now. **Phase 7 will introduce MCP server scoping** (a custom MCP server replacing `Bash`/`Read` defaults with vault-scoped variants); Phase 1 does not anticipate that.

**State Management:**

Two distinct state stores, owned by different layers:

- **Process state** (Rust): `tauri::State<Mutex<Option<u32>>>` holding the spawned PID. Single-session per D-10; Phase 3 refactors to `Mutex<HashMap<SessionId, u32>>`. `register_session_pid` Tauri command writes; the lifecycle hook union reads + clears. This is the ONLY state Rust manages in Phase 1.
- **Conversation state** (frontend, ephemeral): `let messages = $state<Msg[]>([])` in `+page.svelte`. **Phase 1 does NOT persist this to disk** — every app launch is blank per SPEC REQ-6 ("launch always opens to a blank chat"). Cross-launch chat history is explicitly Phase 3 (`--resume <session-id>` mechanism + multi-session sidebar). The `claude` CLI itself owns the *internal* conversation history within a single subprocess invocation; mneme's `messages` array is purely a UI-rendering mirror of stream-json events, not a source of truth.

There is no chat-history-on-disk file in Phase 1 (no `~/.mneme/usage.jsonl`, no `~/.mneme/config.json` — both explicitly out-of-scope per SPEC L100). The only persistence is `localStorage["mneme.layout.split"]` for column dividers (D-02).

**Context Window Strategy:**

mneme **does not implement** prompt summarization, RAG retrieval, sliding-window truncation, or any other context-window-management strategy in Phase 1. Anthropic's model context window (200k tokens for Claude Sonnet) and any compaction logic are owned by the `claude` CLI itself.

mneme exposes only three structural levers, all in `spawn-args.ts`:

1. `--max-turns 30` — caps the tool-use loop at 30 round-trips (assistant → tool_use → user → assistant). This bounds the *total* turn count, not per-turn token count.
2. `--add-dir <SCRATCH>` — bounds the agentic-search filesystem surface. A smaller search surface produces smaller agentic-loop intermediate context.
3. `--exclude-dynamic-system-prompt-sections` — strips auto-prepended planning/state context the CLI would otherwise inject (spike-findings cost-reality: this is what drops first-call cache_creation from ~107k to <20k). mneme does NOT yet inject its own custom system prompt — Phase 9 (REQ-08 anchored / NotebookLM mode) will introduce one; Phase 1's discipline is to *not* customize.

When the cumulative session context approaches the model window, the `claude` CLI handles compaction internally; mneme observes `result.usage.cache_read_input_tokens` rising via dev-console logs but takes no programmatic action.

## 4b. AI Systems Best Practices

> Cross-cutting patterns applied to this Phase 1 framework + system-type combination. The conventional Pydantic-and-async framing assumes a Python AI framework; mneme's stack is TypeScript + Rust + a subprocess CLI, so the same principles map differently — the discipline is identical, the tools are not.

### Structured Outputs from stream-json events (replacing Pydantic schema)

The `claude` CLI's stream-json wire format **already provides a discriminated union schema** for every event — there is no place for an LLM-output-validation step that Pydantic would gate, because the LLM is wrapped by the CLI which already emits typed events. The "structured output" discipline for mneme is: **make the union exhaustive at the type level, dispatch on `evt.type`, and surface unknowns rather than silently dropping them.**

```typescript
// vendor/claude-code-parser/src/types.ts — the canonical typed union (KD-12 + D-13).
// THIS file is the source-of-truth schema; do not duplicate in mneme-side code.
export type StreamEvent =
  | SystemEvent                  // {type:"system", subtype:"init"|"hook_*"|"status", model?, cwd?, ...}
  | StreamDeltaEvent             // {type:"stream_event", ttft_ms?, event: AnthropicSSEPayload}
  | AssistantEvent               // {type:"assistant", message:{content:AssistantBlock[]}}
  | UserEvent                    // {type:"user", message:{content:[ToolResultBlock]}}
  | RateLimitEvent               // {type:"rate_limit_event", ...budget snapshot}
  | ResultEvent;                 // {type:"result", total_cost_usd, duration_ms, usage, stop_reason}

export type AssistantBlock =
  | { type: "text"; text: string }                                  // already streamed — skip
  | { type: "thinking"; thinking?: string; signature?: string }     // encrypted — render indicator only
  | { type: "tool_use"; id: string; name: string; input: unknown };

export type ResultEvent = {
  type: "result";
  total_cost_usd: number;
  duration_ms: number;
  stop_reason: "end_turn" | "max_tokens" | "stop_sequence" | "tool_use" | string;
  usage: {
    input_tokens: number;
    output_tokens: number;
    cache_creation_input_tokens?: number;
    cache_read_input_tokens?: number;
  };
};
```

**Mneme's "validation" rules (analogous to Pydantic retry-on-validation-fail logic):**

| Failure | Phase-1 Behavior | Why |
|---------|------------------|-----|
| `JSON.parse` throws on a stdout line | `try/catch` → `continue` (drop this line) | Rare; partial-line buffer handles the common case. NEVER throw mid-stream — would kill the dispatch loop. |
| `evt.type` is not in the 6-arm union | Default branch → `console.warn("[claude:unknown-event]", evt)` | Anthropic may add new event types in CLI updates; observability over silent drop. |
| `result` event missing required fields (e.g. no `usage`) | Render system bubble "session ended (incomplete result)" | Don't crash; surface to user. |
| `close` fires WITHOUT a prior `result` event | Surface system bubble "stream ended unexpectedly"; do NOT finalize markdown render | Stream may have been killed mid-way (network drop / SIGKILL). Rendering partial markdown breaks code fences (spike-findings §6 pitfall). |

There is **no retry**. mneme is single-user; a malformed CLI output is a CLI bug to file upstream, not a transient to be retried. The dev console is the only logging surface (D-18). Phase-2-or-later evaluation/eval-auditor introduces structured eval logs — Phase 1 does not.

### Async-First Design

Three asynchronous surfaces, each with a distinct concurrency model:

1. **`Command.spawn()` returns `Promise<Child>`** — awaits until the OS fork+exec succeeds. Listeners (`cmd.stdout.on("data" | ...)`) MUST be registered on the `cmd` builder *before* `await cmd.spawn()`, otherwise early stdout chunks are lost (spike-findings tauri-shell-ui.md §4). The validated pattern is: build → register all listeners → spawn.

2. **`cmd.stdout.on("data", cb)`** — fires asynchronously per byte chunk, not per event line. The callback is **synchronous and fast** (line buffer + JSON.parse + 6-arm switch); doing async work inside it (e.g. `await`-ing a render) is the one common mistake that creates re-entrancy bugs because new chunks can arrive during the await.

3. **`invoke("register_session_pid", {pid})`** — round-trips to Rust over Tauri IPC; returns `Promise<void>`. Single fire-and-await per spawn.

```typescript
// CORRECT — listeners registered, then spawn. Callback is sync.
const cmd = Command.create("claude-bin", buildClaudeArgs(prompt));
let buffer = "";
cmd.stdout.on("data", (chunk: string) => {            // sync callback
  buffer += chunk;
  const parts = buffer.split("\n");
  buffer = parts.pop() ?? "";
  for (const raw of parts) {
    if (raw.trim()) try { dispatchEvent(JSON.parse(raw), messages); } catch { /* drop */ }
  }
});
cmd.on("close", finalizeRender);                      // sync callback
const child = await cmd.spawn();                      // await fork+exec only
await invoke("register_session_pid", { pid: child.pid });

// WRONG — async work inside data callback. Re-entrancy: chunk N+1 arrives during await chunk N.
cmd.stdout.on("data", async (chunk: string) => {
  buffer += chunk;
  await someExpensiveRender();                        // <— DO NOT DO THIS
  ...
});

// WRONG — listener registered after spawn. Initial chunks lost.
const child = await cmd.spawn();
cmd.stdout.on("data", ...);                           // <— TOO LATE
```

**Stream vs. await rule of thumb:** stream when emitting *to the user* (chunky monospace `<pre>` text during `text_delta` events), await when *committing to a final, validated artifact* (the markdown + KaTeX render fires only inside the `cmd.on("close")` handler, after a `result` event has been observed). Streaming partial markdown breaks unclosed code fences (spike-findings tauri-shell-ui.md "What to Avoid").

### Prompt Engineering Discipline

Phase 1 **does not author or customize a system prompt.** This is a deliberate restraint:

- `claude` CLI manages its own default system prompt internally. mneme strips the *dynamic* sections via `--exclude-dynamic-system-prompt-sections` (the only system-prompt knob mneme touches in Phase 1) but does NOT replace, append, or wrap the static base prompt.
- **No `--system-prompt` / `--append-system-prompt` flags in Phase 1's spawn-args SSOT.** Adding one would force a versioned-prompt-management story (eval calibration, A/B comparison, regression tests) disproportionate to a Phase-1 shell-foundation goal.
- **Few-shot examples: none in Phase 1.** mneme's prompt path is `<user textarea>` → last positional arg of `claude --print`. No injection of vault content, no inline retrieved chunks, no dynamic prefixing. (Phase 9 anchored mode and Phase 7 KG-grounded retrieval will introduce dynamic prompt prefixing — Phase 1 establishes the discipline that the *unmodified* user prompt is the baseline.)
- **`max_tokens` not configurable from mneme.** The CLI sets its own model-default output cap; mneme does not expose a knob. The structural budget mneme owns is `--max-turns 30` (turn count, not token count).

The discipline expressed in code:

```typescript
// src/lib/spawn-args.ts — the FULL list of args mneme passes. No prompt template, no
// inline examples, no system-prompt customization. Anything not in this list is by
// definition out-of-scope for Phase 1.
return [
  "--print",                                          // non-interactive piped mode
  "--permission-mode", "bypassPermissions",           // tool calls don't prompt
  "--output-format", "stream-json",
  "--include-partial-messages",
  "--verbose",
  "--max-turns", "30",                                // ONLY structural budget mneme owns
  "--add-dir", SCRATCH_DIR,                           // FS scope only — not prompt content
  "--exclude-dynamic-system-prompt-sections",         // ONLY system-prompt knob mneme touches
  promptText,                                         // raw user input — no template, no prefix
];
```

When Phase 9 (REQ-08 anchored mode) introduces `--system-prompt`, this is the file it edits — and an audit-script grep will at that point fail-closed if `--system-prompt` appears without a corresponding governance doc.

### Context Window Management

Cross-reference Section 4 ("Context Window Strategy"). To summarize the discipline here:

- **No RAG, no chunking, no reranking in Phase 1** — these are Phase 4 (document ingestion) and Phase 7 (KG retrieval) concerns.
- **No conversation summarization** — single session, single subprocess; the conversation lives entirely inside the `claude` process and dies with it on Cmd+Q.
- **No autonomous-agent compaction** — the `claude` CLI's own compaction (when context approaches 200k) is delegated; mneme observes `result.usage.cache_read_input_tokens` as a passive signal in dev-console logs.
- **Three structural levers**: `--max-turns 30` (turn cap), `--add-dir <SCRATCH>` (FS surface), `--exclude-dynamic-system-prompt-sections` (system-prompt trim). All in `spawn-args.ts`, all audited.

The Phase 1 acceptance bar for context-window correctness is purely empirical: **fresh session's first prompt has `result.usage.cache_creation_input_tokens` < 20,000** (down from the spike's ~107k baseline; SPEC acceptance criterion). If a user prompt + tool round-trip causes that figure to climb above 20k on subsequent sessions, that signals a regression in `--exclude-dynamic-system-prompt-sections` behavior — to be investigated, not papered over with summarization.

### Cost and Latency Budget

**Cost: $0 per call structurally.** OAuth subscription pricing (KP-04) means there is no per-call billing — the user has paid the monthly Claude Pro/Max fee, and `result.total_cost_usd` is a *theoretical API-equivalent* surfaced for visibility, not a real charge. SPEC Round 4 explicitly deleted the cost-meter UI from Phase 1's scope on this basis; the `total_cost_usd` field is logged to the dev console (D-18) but never rendered to the user.

The structural-cost guard is **`--max-turns 30`**, not a dollar cap. An infinite tool-use loop under OAuth doesn't bill — it consumes the user's daily rate-limit budget, which Anthropic enforces as a separate ceiling (visible in `rate_limit_event` events). Once exhausted, subsequent calls return `429`-style errors until the budget resets.

**Latency: TTFT 2–4s typical (network → Anthropic → first token).** Spike-findings §7 captures `ttft_ms` from the first `stream_event` of the session as the canonical metric; spike-002 echo test recorded ~10.5s total duration for a tool-use round-trip. mneme logs `ttft_ms` to dev console on first stream event (D-18) and `result.duration_ms` on session end. No SLO is enforced in Phase 1 — observability before alerting.

**No caching strategy required at Phase 1.** Two reasons:

1. **No per-call billing**: the conventional reasons for prompt caching (cost savings) don't apply. Anthropic's prompt-cache mechanism *is* used implicitly — `--exclude-dynamic-system-prompt-sections` keeps the static system prompt cache-friendly, and `cache_read_input_tokens` confirms the cache is hot — but mneme owns no exact-match or semantic-cache layer.
2. **Single session per launch**: no cross-session reuse pattern to optimize. Phase 3's multi-session refactor opens this up; Phase 1 does not.

**No sub-task model routing.** A single `claude` subprocess runs a single model per spawn (selected by the CLI from the user's subscription tier). Routing a classification or summarization sub-task to a cheaper model would require an API-key path (Haiku via `ANTHROPIC_API_KEY`) — incompatible with KP-04 and out-of-scope for Phase 1. If/when Phase 7 needs cheap classification (e.g., concept-tag extraction), the candidate path is a local `nomic-embed-text` via Ollama (per STACK.md §10) rather than a second model provider.

## 7. Production Monitoring

**Tracing Tool:** **Arize Phoenix — DEFERRED to Phase 9.** Phase 1 ships **zero production telemetry** by design (D-18). The "production" environment IS one developer's laptop; the only monitoring surfaces are (a) the streaming-dot indicator in the chat UI, (b) `console.log` lines in dev-mode (Cmd+Option+I), and (c) manual `ps aux` / Activity Monitor inspection during dogfood. Phoenix is the locked default for later phases (Phase 7 KG retrieval traces, Phase 9 anchored-mode citation-faithfulness eval) where conversation traces have analytical value — at those phases, the standard `pip install arize-phoenix opentelemetry-sdk` + `phoenix.launch_app()` + framework instrumentation flow lands.

**Key Metrics to Track:**

1. **Subprocess orphan count** — `ps aux | grep -E 'claude|mcp|grep --color|rg' | grep -v grep | wc -l` after each Cmd+Q. Target: 0. Checked manually post-dogfood and via the 5-cycle lifecycle harness; no automated alerting.
2. **TTFT (time to first `text_delta`)** — captured by the `ttft_ms` field on the FIRST `stream_event` of each session (spike-findings §7); logged to dev console only. Target: < 4 s. No alert; visual reference for the developer during dogfood.
3. **Stream completion rate** — % of sessions that emit a `result` event before user-initiated kill or `close` without `result`. Target: > 95% on healthy network. Tracked manually during dogfood by reading the dev console.
4. **Capability audit pass rate** — exit codes of `audit-capabilities.sh` across the 5-day dogfood window + every commit. Target: 100%. Tracked via the git pre-commit hook + the prebuild hook (any non-zero exit blocks the commit/build).
5. **DOMPurify strip count** (optional sanity-check counter) — increment a frontend module-level counter when DOMPurify's `mutated` callback fires; log to dev console at end of session via a `pageshow` listener.
