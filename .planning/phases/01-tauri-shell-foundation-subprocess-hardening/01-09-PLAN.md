### Task 8 — ChatPanel rewrite: streaming render + visual integration

Rewrite the ChatPanel.svelte bubble-rendering loop to match the prototype + fix A-09 / T-1-47:

**Critical streaming render fix**:

Current (wrong): On each text_delta, append raw chars to a `streamingText` string; render it as `<pre>` (monospace). Only on `result` event, replace with `sanitizeMarkdown(streamingText)`.

New (right): Maintain a `streamingMarkdownBuffer: string` per assistant message. On each text_delta:

```ts
// pseudocode
streamingMarkdownBuffer += event.delta.text;
const sanitized = sanitizeMarkdown(streamingMarkdownBuffer);
// Trigger Svelte reactivity: assistantMessage.html = sanitized
```

This makes the AssistantMessage component re-render its `{@html sanitized}` on every chunk. The `marked` parser is forgiving of unfinished markdown (a half-`**bold` or unclosed code fence renders as plain text or an open block). KaTeX inside `$...$` may fall back to plain text on unfinished math — that's fine, on next chunk it'll close and render properly.

Performance: if `text_delta` events fire faster than 60fps, batch via `requestAnimationFrame`:

```ts
// Coalesce multiple chunks within one frame
let pending = '';
let scheduled = false;
function onChunk(text) {
  pending += text;
  if (!scheduled) {
    scheduled = true;
    requestAnimationFrame(() => {
      streamingMarkdownBuffer += pending;
      pending = '';
      scheduled = false;
      // assign reactively
    });
  }
}
```

Layout integration: header reads "{course} / {note}" path (e.g. "COMP3027 / Rod-cutting recurrence" mock); messages scroll in a `.chat-scroll` with messages capped at max-width 720px; usage meter sits between the scroll and the input footer.
