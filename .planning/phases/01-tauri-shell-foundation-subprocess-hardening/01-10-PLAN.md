# 01-10-PLAN — Window-drag capability gap closure (T-1-49)

## Objective

Phase 1 dogfood walk-through (plan 01-07) on 2026-05-09 surfaced a blocker: the
Mneme window cannot be dragged from any edge — clicking and holding on the
36px titlebar (or the `.stage` matte bezel on >=1340px viewports) does not
move the OS window. Pause + handoff via `.continue-here.md` documented 4
prioritized hypotheses (H1 Tauri bridge missing / H2 HMR de-armed listener /
H3 `decorations:true + titleBarStyle:Overlay` flaky / H4 missing capability
permission).

Resume session 2026-05-09–10: H1 devtools probe (`window.__TAURI_INTERNALS__`
present + `getCurrentWindow().startDragging()`) immediately surfaced the H4
signal:

> `Unhandled Promise Rejection: window.start_dragging not allowed.
> Permissions associated with this command: core:window:allow-start-dragging`

Tauri 2.x does NOT include `core:window:allow-start-dragging` in `core:default`.
Every consumer of the `start_dragging` IPC command must declare the permission
explicitly. Both the native `[data-tauri-drag-region]` dispatch path AND the
JS `getCurrentWindow().startDragging()` fallback added during debugging hit
the same Rust permission check; both were rejected by capability gating, not
by any layout/HMR/decorations issue.

Fix: declare the permission via the audit-locked SSOT path
(`scripts/gen-capabilities.ts` → regenerate `default.json` → audit pass).
Tauri's dev mode auto-detected the capabilities file change and triggered a
12.07s cargo rebuild; the new binary loads the permission and drag works.

Cleanup: remove the JS startDragging fallback (~30 lines + a misleading
comment that attributed the symptom to "Tauri 2's data-tauri-drag-region
flakiness on macOS overlay-style titlebars under HMR" — which is wrong) and
the cursor: grab/grabbing visual feedback CSS (the user requested default
cursor restoration once drag worked).

Edit `scripts/gen-capabilities.ts` permissions array:

Tauri's dev watcher detects `src-tauri/capabilities/default.json` change and
triggers cargo rebuild automatically (no manual restart needed).

## Out of scope

- **Plan 01-08 CSP `connect-src` gap (`ipc:` protocol missing)** — the same
  devtools probe surfaced `Refused to connect to ipc://localhost/plugin... not
  in connect-src`. Tauri auto-falls-back to postMessage, so the symptom is
  noisy console errors + slower IPC, not a hard failure. This is a
  plan-01-08 supplementary gap; tracked under plan 01-11 (to be opened via
  `/gsd-execute-phase 1 --gaps-only` so the planner agent writes it
  properly, not retroactively like this plan).

- **Tauri capability scope tightening** — `core:window:allow-start-dragging`
  is a window-grain permission that allows ANY [data-tauri-drag-region]
  surface to drag. We do NOT split it per window or surface; mneme is
  single-window in Phase 1 (REQ-12 multi-session sidebar comes later).
  Revisit when multi-window is added.

- **H2/H3 hypothesis closure** — H4 is sufficient; H2 (HMR) and H3
  (decorations strategy) were not the root cause. They remain documented
  in `.continue-here.md` for post-mortem reference; no further investigation
  needed.
