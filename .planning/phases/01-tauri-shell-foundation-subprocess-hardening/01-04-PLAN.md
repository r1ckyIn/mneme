<objective>
Close the third CRITICAL Phase 1 pitfall — Pitfall 1, subprocess zombies on Cmd+Q. The `claude` CLI calls `setsid()` to detach its process group; `child.kill()` (frontend) and `CommandChild::kill()` (Rust) both send a single signal to the PID only, leaving every grandchild (`mcp` servers, `ripgrep`, file readers) alive across days. After 5 quit cycles, `ps aux` shows accumulating orphans consuming RAM and battery.

This plan ships the Rust state machine (D-10) that fixes this:

- **`SessionRegistry`** (extension-friendly per RESEARCH §8 Risk 1) — `Mutex<HashMap<SessionId, ChildHandle>>` with 0 or 1 entry in Phase 1. Phase 3 (multi-session) inserts more entries with no rip-out.
- **`kill_pgid(pid: u32)`** — `nix::sys::signal::killpg(getpgid(pid), SIGTERM)` → 2s grace → `SIGKILL`. Public function so the integration test can call it directly.
- **Hook union** — `WindowEvent::CloseRequested` ∪ `RunEvent::ExitRequested` both invoke `SessionRegistry::kill_all()`. Tauri issue #9198 shows `ExitRequested` is unreliable on some macOS versions; `CloseRequested` is the partner. Both hooks calling `kill_all` is safe — `Mutex<HashMap>::take()` on the inner map empties on first drain, so the second hook is a no-op.
- **Three Tauri commands** — `register_session_pid` (frontend hands `child.pid` over after spawn), `clear_session_pid` (frontend signals natural close — releases registry slot), `stop_session` (Stop button — runs `kill_all` without app exit per D-19).
- **Setup hook** — `std::fs::create_dir_all(~/.mneme/scratch/)` (idempotent; REQ-10 `--add-dir` target placeholder; plan 01-01 stubbed this — this plan keeps it correct after the lib.rs rewrite).

This plan is **TDD-eligible per RESEARCH §6** — `kill_pgid` against a real `setsid` child tree is a deterministic Rust integration test (`cargo test --test kill_pgid`). RED → GREEN → REFACTOR.

Purpose: Pitfall 1 is the only failure mode in Phase 1 that requires kernel-level signal semantics (PGID vs PID). Getting this right is non-trivial — the spike-002 baseline ships with NO cleanup at all, so this is greenfield (not a port). The 5-cycle bash harness in plan 01-07 is the end-to-end gate; this plan ships the unit-level integration test that the harness depends on.

The setup hook is a re-statement of plan 01-01's baseline — this plan only EXTENDS lib.rs (adds session machinery), does not RESET it.

```rust
// src-tauri/src/session.rs — extension-friendly subprocess registry per RESEARCH §8 Risk 1.
//
// Phase 1 ships the HashMap shape so Phase 3 (multi-session) can insert more
// entries with no rip-out. Phase 1 always has 0 or 1 entry; SessionId is
// hard-coded as 1 in the lib.rs invoke handlers.
//
// kill_all() is the load-bearing method — both WindowEvent::CloseRequested
// and RunEvent::ExitRequested hooks call it. drain_all() empties the map on
// first call, so the second hook invocation is a safe no-op (idempotent).

use std::collections::HashMap;
use std::sync::Mutex;

pub type SessionId = u32;

pub struct ChildHandle {
    pub pid: u32,
    // Phase 3 will add: resume_token: Option<String>, spawned_at: Instant, ...
    // DO NOT add fields in Phase 1 — Phase 3 plan-phase decides the schema.
}

pub struct SessionRegistry {
    inner: Mutex<HashMap<SessionId, ChildHandle>>,
}

impl SessionRegistry {
    pub fn new() -> Self {
        Self { inner: Mutex::new(HashMap::new()) }
    }

    pub fn register(&self, id: SessionId, handle: ChildHandle) {
        self.inner.lock().unwrap().insert(id, handle);
    }

    pub fn drain_one(&self, id: SessionId) -> Option<ChildHandle> {
        self.inner.lock().unwrap().remove(&id)
    }

    pub fn drain_all(&self) -> Vec<ChildHandle> {
        std::mem::take(&mut *self.inner.lock().unwrap())
            .into_values()
            .collect()
    }

    pub fn kill_all(&self) {
        for h in self.drain_all() {
            crate::kill_pgid(h.pid);
        }
    }
}

impl Default for SessionRegistry {
    fn default() -> Self {
        Self::new()
    }
}
```

```rust
// This test isolates the kill_pgid function from the Tauri runtime — we verify

use std::process::Command;
use std::thread;
use std::time::Duration;

fn pid_alive(pid: u32) -> bool {
    use nix::sys::signal::kill;
    use nix::unistd::Pid;
    // Sending signal 0 = liveness probe; returns ESRCH if dead.
    kill(Pid::from_raw(pid as i32), None).is_ok()

fn kill_pgid_eradicates_setsid_child_tree() {
```

```rust
// src-tauri/src/lib.rs — Tauri builder + subprocess lifecycle (D-10 hook union).
//
// Closes T-1-01 (zombie subprocess accumulation on Cmd+Q) by:
//   1. Storing spawned PIDs in a SessionRegistry HashMap (extension-friendly per RESEARCH §8 Risk 1).
//   2. Killing the entire process GROUP (not just the PID) via nix::killpg(getpgid(pid), SIGTERM)
//      → 2s grace → SIGKILL.
//   3. Hooking BOTH WindowEvent::CloseRequested and RunEvent::ExitRequested
//      (Tauri issue #9198: ExitRequested unreliable on some macOS versions).

mod session;

pub use session::{ChildHandle, SessionId, SessionRegistry};

use std::fs;
use std::thread;
use std::time::Duration;

use nix::sys::signal::{killpg, Signal};
use nix::unistd::{getpgid, Pid};
use tauri::{Manager, RunEvent, State, WindowEvent};

// ---------------------------------------------------------------------------
// kill_pgid — load-bearing for REQ-3.
// ---------------------------------------------------------------------------
//
// PUBLIC because the integration test (src-tauri/tests/kill_pgid.rs) calls it.
//
// Pid::from_raw takes i32; CommandChild::pid() returns u32. The `as i32` cast
// is safe for any realistic POSIX PID (RESEARCH §4.3 line 213) — no `unsafe`.
//
// SIGKILL is sent UNCONDITIONALLY after the 2s SIGTERM grace. If the process
// group is already dead, killpg returns ESRCH which we drop with `let _ =`.
// Adding a TOCTOU "is it still alive?" check is forbidden — that introduces
// a race window where a slow-exiting child could be missed.

pub fn kill_pgid(pid_u32: u32) {
    let pid = Pid::from_raw(pid_u32 as i32);
    if let Ok(pgid) = getpgid(Some(pid)) {
        let _ = killpg(pgid, Signal::SIGTERM);
        thread::sleep(Duration::from_secs(2));
        let _ = killpg(pgid, Signal::SIGKILL);
    }
    // If getpgid fails (ESRCH for already-dead pid), silently no-op.
}

}

#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
    tauri::Builder::default()
        .plugin(tauri_plugin_shell::init())
        .manage(SessionRegistry::new())
        .invoke_handler(tauri::generate_handler![
            register_session_pid,
            clear_session_pid,
            stop_session
        ])
        .setup(|_app| {
            // Auto-create ~/.mneme/scratch/ on first launch (REQ-10 --add-dir target).
            // Idempotent — create_dir_all silently no-ops if path exists.
            if let Some(home) = home::home_dir() {
                let _ = fs::create_dir_all(home.join(".mneme/scratch"));
            }
            Ok(())
        })
        .on_window_event(|window, event| {
            // Red-button close on the title bar dispatches WindowEvent::CloseRequested.
            // We do NOT call api.prevent_close() — let the window close after we
            // kill children. See Tauri issue #9198 for why we also need the
            // RunEvent::ExitRequested handler below (some macOS versions silently
            // skip one or the other).
            if matches!(event, WindowEvent::CloseRequested { .. }) {
                window.app_handle().state::<SessionRegistry>().kill_all();
            }
        })
        .build(tauri::generate_context!())
        .expect("error building app")
        .run(|app, event| {
            // Cmd+Q on macOS dispatches NSApplicationTerminate which Tauri 2
            // surfaces as RunEvent::ExitRequested. CloseRequested handler may
            // OR may not have already run; kill_all() is idempotent (drain_all
            // empties the map on first call).
            if matches!(event, RunEvent::ExitRequested { .. }) {
                app.state::<SessionRegistry>().kill_all();
            }
        });
}
```
