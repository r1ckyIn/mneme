# 01-08-PLAN — SvelteKit CSP nonce gap closure

## Objective

Phase 1 dogfood walk-through (plan 01-07) revealed that `npm run tauri dev` opens a **white-screen webview** even though Vite + Rust both compile clean. Root cause: `src/app.html` hard-codes `Content-Security-Policy: ... script-src 'self' 'wasm-unsafe-eval' ...` (per plan 01-01), but SvelteKit's dev mode emits an **inline bootstrap script** with no nonce. The webview enforces the meta CSP, blocks the inline script, SvelteKit hydration never starts → white screen.

Switch to SvelteKit's **nonce-mode CSP** (mode: `'auto'` → dev uses nonce, prod build uses hash). SvelteKit injects both the meta CSP AND the matching nonce on its own inline script, so:

- **Dev:** webview accepts SvelteKit's bootstrap (nonce match) and rejects every other inline script (no nonce).
- **Prod (npm run build):** SvelteKit replaces the placeholder with a SHA-256 hash of the actual inline content; same effect, hash-based.

This closes the gap without weakening CSP semantics — `'unsafe-inline'` is **NOT** added.

## Tasks

### Task 1 — Configure `kit.csp` in `svelte.config.js`

Add `csp` block under `kit`:

```js
kit: {
  adapter: adapter({ ... }),
  csp: {
    mode: 'auto',
    directives: {
      'default-src': ['self'],
      'script-src':  ['self', 'wasm-unsafe-eval'],
      'style-src':   ['self', 'unsafe-inline'],
      'img-src':     ['self', 'data:'],
      'connect-src': ['self', 'ws:', 'http://localhost:*']  // ws: for Vite HMR
    }
  }
}
```

Notes:
- `mode: 'auto'` → dev uses nonce, build uses hash.
- `connect-src` must allow `ws:` and `localhost:*` for Vite HMR; production build inlines this anyway (HMR is dev-only) — narrowing later is REQ-5 v1.x candidate.
- `style-src 'unsafe-inline'` retained — Svelte 5 emits scoped inline styles per component; tightening to nonce-style is a separate gap (track in dependencies.md / v1.x).

Commit: `feat(01-08): configure SvelteKit CSP with nonce mode (REQ-5 dev-shell recovery)`

### Task 2 — Remove hard-coded CSP meta from `src/app.html`

Delete the `<meta http-equiv="Content-Security-Policy" ...>` line. SvelteKit's `%sveltekit.head%` will inject the policy on every response, with the nonce/hash matching its own inline scripts.

After change, `src/app.html` has no `Content-Security-Policy` substring; `%sveltekit.head%` is the only CSP source.

Commit: `feat(01-08): drop hard-coded CSP meta — SvelteKit kit.csp now owns it`
