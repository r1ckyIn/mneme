**Gap closure plan — Backend data safety (Wave 1, parallel-safe with 02-15).**

Closes 3 findings from `02-REVIEW.md` whose root causes all live in the Rust backend:

1. **CR-02 BLOCKER (data loss)** — `import_controller.rs:259-260` gates basename-clash check behind `routes_to_source = category_task != "_inbox" && course_task.is_some()`. Per D-11 `_inbox/` is the COMMON default destination; the gate skips the existence check for every `_inbox`-bound import. Dropping `notes.pdf` twice (different content, same name) silently loses the first file. Fix: lift the existence check to ALL Import-context writes, emit `dest-clash:<path>` prefix in `ImportFailure.reason`, and teach `import-error.ts::classifyImportError` to map the prefix to a friendly "already exists" message.

2. **CR-03 BLOCKER (security/integrity)** — `lib.rs:509-552` canonicalizes `src`/`dst` to `canon_src`/`canon_dst` (used only in the disk-bomb + empty-dst guards) but uses RAW `&src` / `&dst` in `safe_copy_vault` + the post-copy `count_and_sum` verify + `index.reconcile`. Attack vector: `ln -s /tmp/empty ~/new-vault-link` → user picks `~/new-vault-link` → canon_dst resolves to `/tmp/empty` (empty, guard passes) → copy lands at `/tmp/empty` but config persists user-string `~/new-vault-link`. Symlink removal later leaves vault appearing empty. Fix: substitute `&canon_src` / `&canon_dst` for ALL post-canonicalize operations.

3. **WR-01 WARNING (auth UX bug)** — `lib.rs:184-201` returns `Ok(ClaudeAuthStatus { found: false })` when `home::home_dir()` returns `None`. The remediation message tells user to run `claude --version` (which itself depends on HOME) — infinite loop. Fix: add `env_broken: bool` field; Step 2 frontend can surface a distinct "environment misconfigured" message.

**Why TDD mode (per CLAUDE.md TDD rules):** CR-02 is pure backend behavior with deterministic I/O contracts and an established mirror pattern (`source_basename_clash.rs`) → Task 1 RED + Task 3 GREEN. CR-03 is structurally different: the bug is a `raw &src/&dst` vs `&canon_*` mismatch in `move_vault` that cannot be tested without `tauri::State` plumbing. CR-03 is therefore CLOSED BY GREP GATE (Task 4) and Task 2 is supporting invariant pinning, NOT a TDD red→green cycle.

**Parallel-safety:** files touched are disjoint from Plan 02-15 (vault_writer.rs / Onboarding.svelte / Step5AddCourse.svelte / audit-capabilities.sh). Plan 02-14 also touches lib.rs (CR-04 emit events + WR-08 layout race) but is wave-serialized AFTER this plan to avoid merge conflicts on lib.rs.
