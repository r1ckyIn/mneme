**Investigation summary** (RESEARCH L944-957 — option 2 wins):

Tauri 2 exposes drag events on two layers:

1. **DOM layer** (HTML5 `dragenter` / `dragover` / `drop`): fires only when `dragDropEnabled: false`. `event.dataTransfer.types.includes("Files")` works on dragenter (WebKit bug 223517 affects `.items` but NOT `.types`). On drop, `event.dataTransfer.files` gives `File` objects WITHOUT filesystem paths (security model). To write into `_source/`, app must `FileReader.readAsArrayBuffer` then `invoke("write_to_vault", { path, bytes, ... })` — bytes through JS.

2. **Tauri layer** (`getCurrentWebviewWindow().onDragDropEvent(handler)`): fires when `dragDropEnabled: true`. Payload carries OS file PATHS directly (no FileReader). Discrimination of "is this a file drag?" happens because the payload's `paths` array is non-empty for native file drops, empty for text drags.

**Decision**: Use **Tauri layer** (`onDragDropEvent` with `dragDropEnabled: true`). Rationale:
- Direct path access avoids bytes-through-JS (especially valuable for large PDFs).
- D-09 discrimination becomes: handler fires → if `paths.length > 0`, show DropzoneOverlay; otherwise pass through.
- Trade: HTML5 `dragenter` won't fire, so DropzoneOverlay show/hide is driven by Tauri events, not DOM. The Svelte component subscribes to `onDragDropEvent` with the three states it emits (`enter`, `over`, `drop`, `leave`).
