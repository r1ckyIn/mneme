## Deviations from Plan

### §1 — [Rule 4 — Architectural] CLAUDE.md NOT force-added to git history

**Found during:** Task 3 staging (after Tasks 1 + 2 verify passed clean).

**Issue**: Plan task 3 says `git add .planning/dependencies.md CLAUDE.md` and verify line `git diff HEAD~1 HEAD --stat | grep -q 'CLAUDE.md'`. But CLAUDE.md is `.gitignored` per `.gitignore:40` (`CLAUDE.md`) — `git add CLAUDE.md` fails with `The following paths are ignored by one of your .gitignore files`. Workaround would be `git add -f CLAUDE.md` (force) — but this dumps the entire 496-line CLAUDE.md into git history.

**Why this hits Rule 4 (architectural), not Rule 1 (bug-fix)**: r1ckyIn L2 user-global instruction (`~/claude/r1ckyIn_GitHub/CLAUDE.md`) and project CLAUDE.md L1 both state explicitly:

> **CLAUDE.md 绝不推送到 GitHub**（已 .gitignore）

The mneme CLAUDE.md additionally contains 39.5 KB of user-profile / personal device info (MacBook Pro 2019 Intel, macOS Ventura 13.4) / user email / internal STACK.md decisions / KP / KD / REQ / OOS / RQ counts. Force-adding it puts user-personal data into git history that may someday be pushed to a remote.

**Plan vs. user-global rule conflict resolution**: User-global rule wins (it is the hard constraint per CONFIG hierarchy; plan is phase-level). plan-checker did not see this corner because plans typically don't touch CLAUDE.md.

**Action taken**:
1. CLAUDE.md change applied at FS level only (worktree + main repo, identical content).
2. `git add CLAUDE.md` attempted and rejected by `.gitignore` (expected).
3. NOT used `git add -f` (would have violated user-global hard rule).
4. Single commit covers only `dependencies.md`.
5. Plan task 2 verify (`grep -q 'dev-feedback-loop' CLAUDE.md`) still passes because the FS-level change is present.
6. Plan task 3 verify (`git diff HEAD~1 HEAD --stat | grep -q 'CLAUDE.md'`) **deliberately fails** — recorded here so the user can decide one of three follow-ups:
   - **Option A**: Accept current state (FS-level CLAUDE.md change, no git history) — relies on `/gsd-extract-learnings` or future sync to propagate the pointer if CLAUDE.md is ever regenerated.
   - **Option B**: Move the pointer row to a git-tracked file like `.planning/CONVENTIONS.md` or `.planning/PATTERNS.md` (does not currently exist — would be net-new file). Plan-checker preference unknown.
   - **Option C**: Reverse the r1ckyIn L2 `.gitignore` rule for `CLAUDE.md` (project-level only) — major policy change, likely out of scope.
