<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| upstream template → rendered HTML | template controls what the renderer can emit; a forbidden phrasing baked into the example comments could leak if validator misses |
| rendered HTML → human eye | XSS risk if renderer doesn't escape user-supplied content from buckets YAML — but renderer is local-only (no untrusted input) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-01.1-03-01 | Tampering | example article comments contain forbidden-phrasing keywords that grep could accidentally surface | accept | examples are inside HTML comments — `verify.validate-html` parses the rendered DOM (not comments) so forbidden-bucket detection is unaffected. The example block intentionally shows the correct shape (with screenshot + locked-value comparison) so writers internalize the anti-pattern boundary |
| T-01.1-03-02 | Information disclosure | XSS via bucket YAML injection from `verify.render-review-html` | mitigate | renderer in plan 01.1-04 task 7 must HTML-escape all `{{BUCKET_*}}` content (we control the upstream LLM but the bucket content is freeform text — escape to be safe). Document the escape contract in 01.1-04 |

</threat_model>
