## Decisions Made

- **Added `--dry-run` to `gsd-dev-screenshot.mjs` (NOT in PLAN.md task 2 but required by prompt success_criteria #4 + #5).** This is the capability probe that verify-work patch 1 (`automated_ui_verification` step) uses to detect whether the current project has a Tauri bridge. The probe still gates on `dev-server.pid` (consistent with the real invocation path — meaningful only when the dev loop is up); prints `{ready: true, surface: <value>}` to stdout and exits 0 WITHOUT shelling out to dev-invoke.
- **Vitest include glob extended for `.mjs` discovery** (Rule 3 — blocking fix). Without this the test file would not be discovered by `npm test` and the GREEN gate could not run. One-line config delta; mirrors the existing `tests/**/*.test.ts` + `src/**/*.test.ts` patterns.
- **Pre-commit hook constrains TDD ordering: commit RED+GREEN together.** The hook runs vitest on every commit. A pure RED commit (test file only, before implementation) would be blocked. Reconciled by committing the test file + the implementation together in the same atomic commit (`7bef106`). The RED phase was still executed (test file written, run, observed to fail — 7/7 failed before scan-logs.mjs existed) but only the GREEN-passing state lands in git history.
- **2-commit split per natural boundary, not PLAN's single Task-6 atomic commit.** Commit 1 (`5fa869f`) declares the npm-script entries + vitest config. Commit 2 (`7bef106`) ships the implementation. Each commit is independently revertable: revert `7bef106` and the scripts entries point at missing files (which the GSD SDK's structured-error path handles gracefully); revert `5fa869f` and the helper files are present but undeclared in `package.json`. Both states are recoverable.
- **Busy-wait polling (not `setTimeout`) in snapshot.mjs.** The helper must be fully synchronous (npm run lifecycle — no event-loop scheduling surprises). Busy-wait at 80ms spin cost is acceptable for a 3-second deadline poll (~37 iterations max). Phase 01.2 UDS upgrade (RESEARCH spike B2) replaces the poll-tail dance with a synchronous IPC round-trip.
- **Defensive parser-per-line philosophy in scan-logs.mjs.** Each parser returns `null` for non-matching lines AND the scan loop wraps each parser call in try/catch (belt-and-suspenders against future parser regressions). Mirrors plan 01.1-06 D-SF-04 IO-error swallow on the writer side. Verified by malformed-line test scenario.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Vitest config did not discover `.mjs` test files**

- **Found during:** Task 4 (RED phase — about to run `npm test -- gsd-dev-scan-logs`)
- **Issue:** The existing `vitest.config.ts` `include` array (`['tests/**/*.test.ts', 'src/**/*.test.ts']`) excluded `scripts/__tests__/**/*.test.mjs`. Running `npm test` with the new test file present would print "No test files found, exiting with code 0" — the GREEN gate cannot fire and the plan cannot be verified.
- **Fix:** Extended `vitest.config.ts` `include` array to also cover `'scripts/__tests__/**/*.test.mjs'`. Three-element array; existing globs preserved.
- **Threat impact:** zero — the new glob is additive and only affects test discovery.
- **Files modified:** `vitest.config.ts`
- **Verification:** `npm test -- gsd-dev-scan-logs 2>&1 | grep Tests` returns `Tests  7 passed (7)` after fix.
- **Committed in:** `5fa869f` (Task 1 commit, alongside the package.json script declarations).

**2. [Rule 2 - Missing Critical] `--dry-run` flag absent from PLAN.md task 2**

- **Found during:** Task 2 (drafting `gsd-dev-screenshot.mjs`)
- **Issue:** The prompt's success_criteria #4 + #5 require that `npm run gsd-dev-screenshot --dry-run` (with pid file present) prints `{ready: true, surface: <value>}` to stdout. This is the probe used by the GSD upstream verify-work patch 1 (`automated_ui_verification` step → D-UP-01) to detect whether the current project has a Tauri bridge available. PLAN.md task 2's action block did NOT mention `--dry-run`; the plan's example code went straight from argv parse to `spawnSync(devInvoke, ...)`. Without `--dry-run`, verify-work patch 1 cannot detect the bridge without actually triggering a screenshot, which is wasteful and would itself fail if no Tauri window is up.
- **Fix:** Added `--dry-run` flag to argv parser + a short-circuit after the pid-file gate that prints `{ready: true, surface}` to stdout and exits 0. Probe still gates on `dev-server.pid` (semantically correct — the probe is "can verify-work reach the Tauri capability", not "does this Node script load").
- **Threat impact:** zero — `--dry-run` short-circuits before any spawnSync, no new attack surface.
- **Files modified:** `scripts/gsd-dev-screenshot.mjs`
- **Verification:** `node scripts/gsd-dev-screenshot.mjs --dry-run --surface webview` (with pid file present) prints `{"ready":true,"surface":"webview"}`. Without pid file, prints D-BR-02 envelope to stderr as expected.
- **Committed in:** `7bef106` (Task 2/3/4/5 atomic commit).

### Atomic-commit boundary rebalanced (not a deviation per se — explicit decision)

**3. [Rule 1 - Bug-prevention] PLAN.md Task 6 single-commit prescription conflicts with pre-commit hook**

- **Found during:** Task 4 RED phase (attempted to commit the test file alone before implementation existed)
- **Issue:** The mneme repo's pre-commit hook runs `npm test` on every commit (Phase 1 D-XX testing infra). A pure RED commit (`test(...)` with no implementation) makes the hook block the commit — vitest fails because the script-under-test doesn't exist yet. PLAN.md Task 6 prescribed a single atomic commit landing all 5 files, but the natural split is "declarations first, implementation second" — and the implementation must include the passing tests in the same commit so the hook doesn't block.
- **Fix:** Two commits instead of one: `5fa869f` (package.json + vitest.config.ts) + `7bef106` (all 4 helper files). Each commit is independently revertable, which is the original intent of the atomic-boundary rule.
- **Verification:** `git log --oneline -2` shows both commits with conventional commit subject lines; `git diff 5fa869f^ HEAD --stat` shows 6 files across the 2 commits.
