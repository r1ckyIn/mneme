## E6 Errata Handling

Per RESEARCH.md R5 (Safari 16 / macOS 13.4 WKWebView): `largest-contentful-paint` PerformanceObserver entry type was added to Safari only in 26.2 (December 2025); the dev surface targets 13.4 Intel Mac. Forwarder strategy:

1. Each `observe({type:'X'})` call wrapped in its own try/catch — one unsupported type does not abort the others.
2. On `TypeError` (Safari's behavior for unsupported types) the forwarder swallows silently EXCEPT for `largest-contentful-paint`, where it emits a single-shot `[forwarder] LCP unavailable on this WebKit version, skipped` info line via the captured `origConsole.info` reference. This makes a future Safari upgrade observable without code change — the info log will simply stop appearing.
3. `__mnemeDevSnapshot__.performance.lcp_ms` remains `null` (typed as `number | null` per D10) when LCP observer fails to install. FCP / CLS / longtask continue to populate as their observers install successfully.

Tested via `R1 — LCP captured (Safari 16 graceful fallback per E6)` describe block in console-forwarder.test.ts: override `PerformanceObserver.prototype.observe` to throw TypeError when called with `largest-contentful-paint`, assert `installConsoleForwarder()` does NOT throw.
